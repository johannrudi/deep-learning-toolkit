# Plan: Gradient Penalties, Finite-Difference Lipschitz Penalties, and Spectral Norm Regularization

## Context

A Wasserstein GAN trains a critic $D$ whose Lipschitz constant must stay bounded. The toolkit has two mechanisms for this. The first is the autograd gradient penalty in `dlk/loss/wasserstein_gan.py`, which differentiates the critic with respect to its inputs and then differentiates that gradient again during the training step (double backward). The second is spectral normalization of linear layers in `dlk/nets/mlp.py`. This document records both as they exist today (Part A). It plans four finite-difference penalties that need only first-order autograd (Part B) and a spectral norm regularizer that penalizes the weights' spectral norms in the loss (Part C). Part D compares the cost of all methods in forward and backward passes.

**Why the change.** `torch.compile` compiles the critic's backward pass with AOTAutograd, and AOTAutograd does not support double backward. A compiled critic combined with the gradient penalty fails with `RuntimeError: This backward function was compiled with non-empty donated buffers ...` on GPU, or with `torch.compile with aot_autograd does not currently support double backward` on CPU. The `eager` keyword added to the gradient penalties works around this by running the penalty's critic forward pass uncompiled, but the penalty's forward, backward, and double backward then run at eager speed. A finite-difference penalty only evaluates the critic, so the whole critic step stays compiled.

**Current state and gaps.**

- The gradient penalties (`gradient_norm_sq`, `gradient_penalty_lip`, `gradient_penalty_opt`) have tests for the compiled path in `tests/loss/test_wasserstein_gan.py` but no frozen regression values.
- Spectral normalization exists only in `MLPResNet`, `ResidualBlock`, and `AttentionBlock`. It does not give a global Lipschitz bound while `LayerNorm` (in every `ResidualBlock`) or self-attention is present, and no convolutional network family offers it.
- There is no penalty that works with a compiled critic without the `eager` workaround.
- There is no loss-based alternative to spectral normalization that leaves the architecture unchanged and works for any network family.
- `DiscriminatorRegularizerFn` in `dlk/opt/train_gan.py` receives the critic but not the critic outputs that the training step has already computed, so a regularizer cannot reuse them.

**Research conclusion.** A difference quotient $|D(x) - D(x')| / \|x - x'\|$ bounds the Lipschitz constant from below and needs only critic evaluations. The literature uses it with pairs on real-to-generated segments and at real and generated endpoints (Petzka et al. 2018; Wei et al. 2018). It also uses it with an adversarially chosen perturbation found by one power-iteration step (Terjék 2020, building on Miyato et al. 2018 VAT). Random small perturbations are the naive baseline. The adversarial variant comes closest to the gradient norm, because it searches for the steepest direction. Spectral norm regularization (Yoshida and Miyato 2017) adds the squared spectral norms of the weights to the loss. It needs no critic evaluation at all, so its cost does not grow with the batch size.

**Settled design decisions.**

- Four public functions, one per pair strategy: `gradient_penalty_lip_fd_segment`, `gradient_penalty_lip_fd_endpoint`, `gradient_penalty_lip_fd_adversarial`, `gradient_penalty_lip_fd_random`. They share one private difference-quotient helper, and each has only its own parameters.
- The endpoint variant reuses the critic outputs through opt-in keywords. The training loop passes `x_gen_batch`, `d_outputs_gen`, and `d_outputs_data` only to a regularizer that declares them by name (or accepts `**kwargs`). Existing regularizer closures are unchanged.
- The random-perturbation variant is implemented as a public baseline with a docstring warning about its weakness in high dimensions.
- Spectral norm regularization is a stateful class `SpectralNormRegularizer` in a new module `dlk/loss/spectral_norm.py`. It holds the power-iteration vectors per layer (not checkpointed, warm-started on the first call). Its `__call__` matches `DiscriminatorRegularizerFn`, so an instance works directly as `d_reg_fn`, and its `penalty(net)` method works on any network.
- The regularizer supports both published forms through `max_norm`: `max_norm=None` (default) gives Yoshida and Miyato's $\frac{\lambda}{2} \sum_l \sigma(W_l)^2$, and `max_norm=k` gives the hinge form $\frac{\lambda}{2} \sum_l \mathrm{relu}(\sigma(W_l) - k)^2$.
- `one_sided` defaults to `True` for all variants. `gradient_penalty_lip_fd_segment` and `gradient_penalty_lip_fd_endpoint` accept `one_sided=False` as the analog of `gradient_penalty_opt`. The adversarial and random variants are one-sided only, because the quotient in an arbitrary direction has no target value of 1.

**Core principle.** Every new penalty is a function of critic forward evaluations or of the critic's weights, and its only backward pass is the training step's own first-order backward. Additions are opt-in only, and no existing signature changes. Consequences:

- The new penalties need no `eager` keyword and work with a compiled critic as is. The adversarial variant's direction search takes a first-order input gradient without `create_graph`, which AOTAutograd supports. The spectral norm regularizer never calls the critic, so compilation does not affect it.
- `DiscriminatorRegularizerFn`, the consumer closures in `fhn_gan` and `mops_gan`, and the existing gradient penalties need no changes.
- The existing GAN loop regression test (`tests/opt/test_train_single_process_regression.py`) must stay green unchanged. Its regularizer declares none of the opt-in keywords.

## Terminology

- **Critic / discriminator**: the network $D$ that scores samples. In a WGAN it estimates the Wasserstein distance and is called the critic; the code calls it `d_net`.
- **Lipschitz constant**: the smallest $L$ with $|D(x) - D(x')| \le L \|x - x'\|$ for all $x, x'$. For a differentiable $D$ it equals $\sup_x \|\nabla_x D(x)\|$.
- **Gradient penalty (GP)**: a loss term on $\|\nabla_x D\|$ at sampled points, computed with autograd.
- **Double backward**: differentiating a gradient. The GP loss depends on $\nabla_x D$, so its derivative with respect to the parameters $\theta$ needs the mixed second derivative $\partial_\theta \nabla_x D$. In PyTorch this requires `torch.autograd.grad(..., create_graph=True)`.
- **AOTAutograd**: the part of `torch.compile` that traces and compiles the backward pass ahead of time. It compiles one backward pass and cannot differentiate that backward again.
- **Donated buffers**: an AOTAutograd optimization that lets the compiled backward reuse saved activations in place. It requires a single backward pass without `create_graph`.
- **Force-eager stance**: `torch.compiler.set_stance("force_eager")`, a context manager under which compiled functions run their original Python code uncompiled.
- **Spectral norm** $\sigma(W)$: the largest singular value of a matrix $W$, equal to its operator norm $\max_{h \neq 0} \|Wh\| / \|h\|$.
- **Power iteration**: the iterative method that estimates the largest singular value and its singular vectors $u, v$ using only matrix-vector products.
- **Parametrization**: a PyTorch mechanism (`torch.nn.utils.parametrize`) that recomputes a module attribute such as `weight` from a stored raw tensor on every access.
- **Difference quotient** $q(x, x')$: $|D(x) - D(x')| / \|x - x'\|$, the average slope of $D$ between two points.
- **Interpolate** $\hat{x}$: a random point on the segment between a real sample and a generated sample.
- **One-sided / two-sided penalty**: one-sided penalizes only slopes above the target $k$; two-sided penalizes any deviation from $k$.
- **Power-iteration direction search**: finding the input direction in which $D$ changes fastest, as in virtual adversarial training (VAT).
- **Opt-in keywords**: keyword arguments the training loop passes to a regularizer only if the regularizer's signature declares them.
- **Spectral normalization vs spectral norm regularization**: normalization divides each weight by its spectral norm inside the forward pass (a hard bound, part of the architecture); regularization adds the spectral norms to the loss (a soft pressure, independent of the architecture).
- **Cost unit $F$**: the cost of one critic forward pass on a batch of $B$ samples. Part D expresses all costs in multiples of $F$.

## Part A: Current implementation

### A.1 Wasserstein GAN and the Lipschitz constraint

The Wasserstein-1 distance between the data distribution $P_r$ and the generator distribution $P_g$ has the Kantorovich–Rubinstein dual form (Villani 2009; Arjovsky et al. 2017)

$$W_1(P_r, P_g) = \sup_{\|f\|_L \le 1} \; E_{x \sim P_r}[f(x)] - E_{x \sim P_g}[f(x)].$$

The critic $D_\theta$ approximates the maximizer $f$. `wasserstein_loss_fn` (`dlk/loss/wasserstein_gan.py`, pre-change line 10) implements

$$\ell_D = -E[D(x_\mathrm{data})] + E[D(x_\mathrm{gen})], \qquad \ell_G = -E[D(x_\mathrm{gen})].$$

Any $K$-Lipschitz critic yields $K \cdot W_1$, so the constraint only has to bound the Lipschitz constant, and the exact value of $K$ does not matter. For the optimal critic $f^*$ and an optimal coupling $\pi^*$ of $P_r$ and $P_g$, $f^*(x) - f^*(y) = \|x - y\|$ holds $\pi^*$-almost surely. Consequently $f^*$ has gradient norm 1 on the segments between coupled points (Gulrajani et al. 2017, Proposition 1). This fact motivates both the two-sided gradient penalty and the pair choices in Part B.

### A.2 Autograd gradient penalty

**Mathematics.** With $x_\mathrm{data} \sim P_r$, $x_\mathrm{gen} \sim P_g$, and $\epsilon \sim U(0, 1)$ per sample,

$$\hat{x} = \epsilon \, x_\mathrm{data} + (1 - \epsilon) \, x_\mathrm{gen}, \qquad g = \nabla_{(x, y)} D(\hat{x}, y).$$

For a conditional critic the gradient includes the conditioning input $y$, and `gradient_norm_sq` returns $\|g\|^2 = \|\nabla_x D\|^2 + \|\nabla_y D\|^2$ per sample.

- `gradient_penalty_opt` implements the two-sided penalty of WGAN-GP (Gulrajani et al. 2017): $\mathcal{R} = E[(\|g\| - 1)^2]$.
- `gradient_penalty_lip` implements a one-sided variant in the spirit of WGAN-LP (Petzka et al. 2018), applied to the squared norm with a margin $\varepsilon$ (argument `eps`) and target $k$ (argument `lip`): $\mathcal{R} = E[\mathrm{relu}(\|g\|^2 + \varepsilon - k^2)]$. WGAN-LP itself uses $E[\mathrm{relu}(\|g\| - 1)^2]$; the code's form penalizes the same set of points, with a different shape of penalty.

**Why double backward.** The parameter gradient of the penalty is

$$\partial_\theta \|\nabla_x D_\theta(\hat{x})\|^2 = 2 \, (\nabla_x D_\theta)^\top \, \partial_\theta \nabla_x D_\theta(\hat{x}),$$

which contains the mixed second derivative. `torch.autograd.grad(..., create_graph=True)` (pre-change line 86) records the graph of the gradient computation so that `loss.backward()` can differentiate it. Without `create_graph=True`, the gradient is detached and the penalty contributes nothing to the critic's update. `retain_graph=True` and `only_inputs=True` were removed because the first defaults to `create_graph` and the second is deprecated and ignored.

**Compile workaround.** All three functions take `eager: bool = False`. With `eager=True`, `gradient_norm_sq` runs the critic forward pass under `torch.compiler.set_stance("force_eager")`; otherwise it uses `contextlib.nullcontext()` so a stance set by the caller is left alone. This works for every wrapping the toolkit produces (compiled `forward` from `dlk/opt/compile.py:compile_net_from_params`, DDP wrapping) because it does not unwrap the module. Tests in `tests/loss/test_wasserstein_gan.py`:

- `test_compiled_critic_fails_without_eager` documents the failure on the `aot_eager` backend.
- `test_compiled_critic_with_eager_matches_uncompiled` checks that parameter gradients match an uncompiled critic, for both penalties, with and without `y_data`.
- `test_eager_does_not_leak_into_later_calls` checks with a compile counter that the stance does not persist.

The consumer `fhn_gan/pytorch/train_gan.py` already passes `eager=True`; `mops_gan/run.py` does not compile the critic.

### A.3 Spectral normalization

**Mathematics.** Spectral normalization (Miyato et al. 2018) replaces each weight matrix by $\bar{W} = W / \sigma(W)$, so that each linear layer is 1-Lipschitz. The spectral norm is estimated by power iteration on persistent vectors $u, v$:

$$v \leftarrow \frac{W^\top u}{\|W^\top u\|}, \qquad u \leftarrow \frac{W v}{\|W v\|}, \qquad \sigma(W) \approx u^\top W v.$$

One iteration runs per training forward pass. Since Lipschitz constants multiply under composition,

$$\mathrm{Lip}(f_L \circ \dots \circ f_1) \le \prod_{l=1}^{L} \mathrm{Lip}(f_l),$$

the network is 1-Lipschitz if every layer is. This holds for linear layers with $\bar{W}$, ReLU, and the residual combination $0.5 \, h_\mathrm{skip} + 0.5 \, h_\mathrm{block}$ used in `ResidualBlock` and `AttentionBlock`. The bound is loose: a measured spectrally normalized `MLPResNet` had a largest input-gradient norm of about 0.3. This is valid for WGAN (any $K$ works) but can limit the critic's capacity.

**Implementation.**

- `MLPResNet(enable_spectral_norm=True)` wraps every `nn.Linear` layer with `torch.nn.utils.parametrizations.spectral_norm`: the input layer, both embedding layers, the output layer, and the block layers (`dlk/nets/mlp.py`, search for `spectral_norm(`). The projections inside `nn.MultiheadAttention` stay unwrapped.
- `set_init_parameters` (`dlk/nets/utils.py`, search for `_get_spectral_norm`) gives spectrally normalized layers an orthogonal weight. All singular values are then 1 and the layer starts norm-preserving (Anil et al. 2019); Xavier's `gain` would be divided out anyway. After initialization it re-syncs $u, v$ with 15 power-iteration steps, as registration does. This uses the private torch methods `_SpectralNorm._reshape_weight_to_matrix` and `_SpectralNorm._power_method`.
- Tests: `tests/nets/test_nets_utils.py` (orthogonal init survives a forward pass for `Linear` and `Conv1d`; eval mode sees a re-synced $\sigma = 1$; plain layers keep Xavier) and `tests/nets/test_mlp.py::test_mlpresnet_spectral_norm_wraps_every_linear`.
- Checkpoints saved before the switch from the legacy `nn.utils.spectral_norm` do not load, because parameter names changed from `weight_orig`, `weight_u`, `weight_v` to `parametrizations.weight.original`, `parametrizations.weight.0._u`, `parametrizations.weight.0._v`.

**Limitations of the global bound.**

- `LayerNorm` divides by the per-sample standard deviation, so its local Lipschitz constant grows without bound on nearly constant inputs (measured Jacobian norm of about 305). `ResidualBlock` has a commented-out assertion with a `TODO` for this (`dlk/nets/mlp.py`, pre-change lines 505–506).
- Dot-product self-attention is not Lipschitz (Kim et al. 2021).
- Dropout scales activations by $1/(1-p)$ during training.
- For convolutions, `spectral_norm` normalizes the kernel reshaped to a matrix of shape (out channels, in channels × kernel size). The convolution operator's norm can be larger: a measured 3×3 `Conv2d` with padding 1 had operator norm 1.68 while its reshaped norm was 1. Exact or tighter bounds come from the FFT method (Sedghi et al. 2019) or from power iteration on the convolution operator itself (Gouk et al. 2021; Farnia et al. 2019).

**Spectral norm penalties.** A soft version adds the spectral norms to the loss instead of dividing by them. Part C plans it.

## Part B: Finite-difference Lipschitz penalties

### B.0 Shared formulation

For a pair $(x_a, x_b)$ with a shared conditioning input $y$, the difference quotient is

$$q(x_a, x_b) = \frac{\|D(x_a, y) - D(x_b, y)\|}{\max(\|x_a - x_b\|, \delta)},$$

with a small $\delta$ (argument `min_dist`) that guards against division by zero. The penalties are

$$\mathcal{R}_\mathrm{one} = E[\mathrm{relu}(q - k)^2], \qquad \mathcal{R}_\mathrm{two} = E[(q - k)^2].$$

By the mean value theorem, $q(x_a, x_b) \le \sup_{z \in [x_a, x_b]} \|\nabla_x D(z)\|$. A difference quotient is therefore a lower bound on the local Lipschitz constant, and a finite-difference penalty enforces the constraint more loosely than a gradient penalty at the same points. As $x_b \to x_a$ along a unit direction $u$, $q \to |\nabla_x D(x_a)^\top u|$, the directional derivative. The choice of direction decides how close the penalty comes to $\|\nabla_x D\|$, and the four variants differ exactly in that choice.

Because pairs share $y$, the penalties constrain the slope in $x$ only. The gradient penalties, by contrast, include $\nabla_y D$.

### B.1 Segment pairs: `gradient_penalty_lip_fd_segment`

**Mathematics.** Two points on each real-to-generated segment, with $t_a, t_b \sim U(0,1)$ per sample:

$$x_a = t_a x_\mathrm{data} + (1 - t_a) x_\mathrm{gen}, \qquad x_b = t_b x_\mathrm{data} + (1 - t_b) x_\mathrm{gen},$$

$$q = \frac{|D(x_a) - D(x_b)|}{|t_a - t_b| \, \|x_\mathrm{data} - x_\mathrm{gen}\|}.$$

$q$ is the average slope of $D$ along the segment between $x_a$ and $x_b$, in the direction $u = (x_\mathrm{data} - x_\mathrm{gen}) / \|x_\mathrm{data} - x_\mathrm{gen}\|$. That is the direction in which the optimal critic has slope 1 on coupled pairs (A.1). Real and generated samples in a batch are paired at random, not by an optimal coupling, so the two-sided form is as heuristic here as `gradient_penalty_opt` is.

**Literature.** Gulrajani et al. 2017 (sampling along segments, Proposition 1); Petzka et al. 2018 (one-sided penalty); Wei et al. 2018 (difference-quotient consistency term).

**Signature.** `gradient_penalty_lip_fd_segment(d_net, x_gen, x_data, y_data, lip=1.0, one_sided=True, min_dist=1e-6, device=None, dlog=None)`.

**Cost.** Two critic forward passes with the batch shape of the loss terms, so a compiled critic reuses its graph. A single concatenated forward pass of $2B$ samples would force a recompile.

### B.2 Endpoint pairs: `gradient_penalty_lip_fd_endpoint`

**Mathematics.** The quotient at the real and generated endpoints themselves:

$$q_i = \frac{|D(x_{\mathrm{data},i}) - D(x_{\mathrm{gen},i})|}{\max(\|x_{\mathrm{data},i} - x_{\mathrm{gen},i}\|, \delta)}.$$

$q_i$ is the average slope over the whole segment, so it is the loosest of the segment-based bounds. Its numerator reuses the critic outputs of the Wasserstein loss, so the penalty costs no extra critic evaluation.

**Literature.** Villani 2009 and Gulrajani et al. 2017 (the optimal critic satisfies $q = 1$ on coupled pairs); Wei et al. 2018.

**Signature.** `gradient_penalty_lip_fd_endpoint(x_gen, x_data, d_outputs_gen, d_outputs_data, lip=1.0, one_sided=True, min_dist=1e-6, dlog=None)`. It takes no `d_net`, and consumers call it from a closure that declares the opt-in keywords (Section 6).

**Loop support.** Because the loop passes a single generated sample positionally (Section 10), the closure must use the opt-in `x_gen_batch` for the distance. The opt-in outputs are computed under autocast and may be `bfloat16`; the loop casts them to `float32` before passing them, matching the full-precision contract of `d_reg_fn`. The cast keeps the autograd connection, so the penalty's gradient flows through the same critic graph as the loss in the single `loss.backward()`.

### B.3 Adversarial direction: `gradient_penalty_lip_fd_adversarial`

**Mathematics.** Adversarial Lipschitz Regularization (Terjék 2020) searches for the perturbation that most violates the constraint:

$$r^* = \arg\max_{\|r\| \le \rho} |D(x) - D(x + r)|,$$

approximated by one power-iteration step as in virtual adversarial training (Miyato et al. 2018, VAT). Starting from a random direction $d \sim \mathcal{N}(0, I)$ of size $\xi$,

$$r_0 = \xi \, \frac{d}{\|d\|}, \qquad g = \nabla_r \, |D(x) - D(x + r)| \big|_{r = r_0}, \qquad r_\mathrm{adv} = \rho \, \frac{g}{\|g\|},$$

$$\mathcal{R} = E[\mathrm{relu}(q(x, x + r_\mathrm{adv}) - k)^2].$$

For small $\xi$, $g$ is parallel to $\nabla_x D(x)$, so $q(x, x + r_\mathrm{adv}) \approx \|\nabla_x D(x)\|$. For a linear critic this is exact after one step. The evaluation points $x$ are the interpolates $\hat{x}$ of A.2, which makes results comparable with the gradient penalty.

**Implementation notes.**

- $g$ is taken with `torch.autograd.grad(..., inputs=r)` without `create_graph`, and $r_\mathrm{adv}$ is detached. The penalty is then an ordinary function of two critic evaluations.
- The direction search runs on `dlk.opt.distributed.unwrap_net(d_net)` (pre-change line 510), so it does not arm DDP's gradient reducer for a backward that never reduces parameter gradients.
- $D(x)$ is evaluated once with gradients for the penalty; the search uses its detached value.
- $\xi$ and $\rho$ are absolute distances in input units (`xi=1e-2`, `radius=1e-1` as starting defaults, flagged for tuning in Section 11).

**Literature.** Terjék 2020 (ALR); Miyato et al. 2018 VAT (power-iteration approximation).

**Signature.** `gradient_penalty_lip_fd_adversarial(d_net, x_gen, x_data, y_data, lip=1.0, xi=1e-2, radius=1e-1, min_dist=1e-6, device=None, dlog=None)`.

**Cost.** Three critic forward passes and one first-order input backward pass.

### B.4 Random perturbations: `gradient_penalty_lip_fd_random` (baseline)

**Mathematics.** With $u$ uniform on the unit sphere in $\mathbb{R}^d$ and radius $\rho$,

$$x' = \hat{x} + \rho \, u, \qquad \mathcal{R} = E[\mathrm{relu}(q(\hat{x}, x') - k)^2].$$

For small $\rho$, $q \approx |\nabla_x D(\hat{x})^\top u|$, and $E[(\nabla_x D^\top u)^2] = \|\nabla_x D\|^2 / d$. The penalty sees only about a $1/\sqrt{d}$ fraction of the slope, so in high dimension it barely constrains the critic. This is why it is kept as a baseline for ablations only.

**Literature.** Kodali et al. 2017 (DRAGAN, which penalizes gradients at noise-perturbed data points); Miyato et al. 2018 VAT (random directions as the starting point that power iteration improves).

**Signature.** `gradient_penalty_lip_fd_random(d_net, x_gen, x_data, y_data, lip=1.0, radius=1e-1, min_dist=1e-6, device=None, dlog=None)`.

**Cost.** Two critic forward passes.

## Part C: Spectral norm regularization

### C.1 Mathematics

For every weighted layer $l$ with weight $W_l$ reshaped to a matrix $\tilde{W}_l$ (shape out features × everything else, as `spectral_norm` does for convolutions), the regularizer is

$$\mathcal{R}_\mathrm{SN} = \frac{\lambda}{2} \sum_l \sigma(\tilde{W}_l)^2 \quad (\texttt{max\_norm=None}), \qquad \mathcal{R}_\mathrm{SN} = \frac{\lambda}{2} \sum_l \mathrm{relu}\big(\sigma(\tilde{W}_l) - k\big)^2 \quad (\texttt{max\_norm}=k).$$

The first form is spectral norm regularization as published (Yoshida and Miyato 2017). The second is its hinge variant, which only acts on layers above $k$.

Each $\sigma$ is estimated as in spectral normalization (A.3), with a persistent left singular vector $u_l$ and $n$ power-iteration steps per call (default $n = 1$):

$$v_l \leftarrow \frac{\tilde{W}_l^\top u_l}{\|\tilde{W}_l^\top u_l\|}, \qquad u_l \leftarrow \frac{\tilde{W}_l v_l}{\|\tilde{W}_l v_l\|}, \qquad \sigma_l = u_l^\top \tilde{W}_l v_l.$$

The iteration runs under `torch.no_grad()`, and $u_l, v_l$ enter $\sigma_l$ as constants. If $u_l, v_l$ are the top singular vectors, $\partial \sigma_l / \partial \tilde{W}_l = u_l v_l^\top$. The parameter gradient is then the rank-one matrix

$$\frac{\partial \mathcal{R}_\mathrm{SN}}{\partial \tilde{W}_l} = \lambda \, \sigma_l \, u_l v_l^\top \quad \text{or} \quad \lambda \, \mathrm{relu}(\sigma_l - k) \, u_l v_l^\top,$$

which autograd produces from $\sigma_l = u_l^\top \tilde{W}_l v_l$ with first-order backward only.

**Relation to the Lipschitz constraint.** For a critic built from weighted layers and 1-Lipschitz activations, $\mathrm{Lip}(D) \le \prod_l \sigma_l$ (A.3). The hinge form with $k = 1$ pushes every factor toward at most 1 and is therefore a soft version of spectral normalization that leaves the architecture unchanged. The published form also shrinks layers already below 1. It acts like weight decay on the top singular value, which Yoshida and Miyato motivate by generalization. Liu et al. 2019 observe that a collapse of the critic's singular values in spectrally normalized GANs precedes mode collapse, which argues against shrinking layers that are already below the target; the hinge form avoids that. The limitations of A.3 carry over: `LayerNorm`, self-attention, and dropout break the product bound, and for convolutions $\sigma(\tilde{W}_l)$ is the reshaped norm, not the operator norm.

**Related, not planned.** Parseval networks (Cisse et al. 2017) penalize $\frac{\beta}{2} \|W^\top W - I\|_F^2$, which constrains all singular values instead of the largest. The penalty needs a full matrix product per layer and is left out of scope.

**Literature.** Yoshida and Miyato 2017; Miyato et al. 2018 (power iteration for $\sigma$); Liu et al. 2019; Cisse et al. 2017.

### C.2 Design: `SpectralNormRegularizer`

- Module `dlk/loss/spectral_norm.py` (new). Constructor `SpectralNormRegularizer(penalty_weight=1.0, max_norm=None, n_power_iterations=1, n_warmup_iterations=15, seed=0)`, where `penalty_weight` is $\lambda$.
- `penalty(net) -> torch.Tensor` iterates over `unwrap_net(net).named_modules()` and covers every module in `WEIGHTED_LAYER_COMPATIBLE_TYPES` (`dlk/nets/utils.py`: `Linear`, `Conv1d/2d/3d`, `ConvTranspose1d/2d/3d`). It skips layers whose weight is already spectrally normalized, found with `get_spectral_norm` (Section 4), because their $\sigma$ is 1 by construction. `ConvTranspose` weights are reshaped along dimension 1, as `spectral_norm` does.
- `__call__(d_net, x_gen, x_data, y_data, *, dlog=None)` matches `DiscriminatorRegularizerFn`. It returns `penalty(d_net)` and logs `sn_max` and `sn_mean` of the $\sigma_l$. An instance can be passed as `d_reg_fn` directly.
- State: a dictionary from qualified module name to $u_l$. Entries are created on the first call with `n_warmup_iterations` steps from a random start drawn from a local `torch.Generator` seeded with `seed`, so that all DDP ranks start from the same $u_l$. An entry is recreated when the layer's shape, device, or dtype changes. The state is not part of any `state_dict`; after a restart, the warm-up re-converges it.
- The regularizer runs in the loop's full-precision section, outside autocast and outside the compiled critic forward.

## Part D: Cost comparison

**Unit and assumptions.** $F$ is the cost of one critic forward pass on a batch of $B$ samples, and $P$ is the number of critic weights. For an MLP critic $F \approx B P$ multiply-adds; for a convolutional critic $F$ is larger by the number of spatial positions. The estimates use common rules of thumb: a first-order backward pass costs about $2F$ (input and weight gradients), a backward pass for input gradients only about $1F$, and differentiating a recorded backward graph about twice that graph's cost. All numbers are estimates. The verification step (Section 9) measures them.

**Reference.** A critic step without a regularizer runs two forward passes for the loss ($x_\mathrm{data}$ and $x_\mathrm{gen}$) and one backward pass through both: about $2F + 4F = 6F$.

| Method | Extra critic forward passes | Extra backward work | Double backward | Other work per step | Extra cost | Compiled critic | What is constrained |
|---|---|---|---|---|---|---|---|
| GP `gradient_penalty_lip`, `gradient_penalty_opt` (A.2) | 1 at $\hat{x}$ | input backward with `create_graph` ($\approx 2F$), then differentiation of that graph in `loss.backward()` ($\approx 4F$ to $6F$) | yes | none | $\approx 7F$ to $9F$ | only with `eager=True`, and then the penalty runs uncompiled | gradient norm at $\hat{x}$ (soft) |
| Spectral normalization (A.3) | 0 | backward through $W / \sigma(W)$, $O(P)$ | no | one power iteration per layer in each training forward, $\approx 2P = 2F/B$ per forward pass | $\approx 6F/B$ (negligible) | yes | every layer $\sigma \le 1$ (hard, reshaped norm for convolutions) |
| FD segment (B.1) | 2 | backward through the 2 forwards, $\approx 4F$ | no | none | $\approx 6F$ | yes | slope along the segment direction (soft, lower bound) |
| FD endpoint (B.2) | 0 | none: the penalty's gradient joins the loss's existing critic outputs | no | $O(B d)$ for distances | $\approx 0$ | yes | average slope between real and generated sample (soft, loosest lower bound) |
| FD adversarial (B.3) | 3 | input-only backward for the direction search ($\approx 1F$) and backward through 2 forwards ($\approx 4F$) | no | none | $\approx 8F$ | yes | slope in the steepest direction ($\approx$ gradient norm, soft) |
| FD random (B.4) | 2 | backward through the 2 forwards, $\approx 4F$ | no | none | $\approx 6F$ | yes | slope in a random direction ($\approx 1/\sqrt{d}$ of the gradient norm, soft) |
| Spectral norm regularization (C) | 0 | rank-one gradient per layer, $O(P)$ | no | $n$ power iterations and one $\sigma$ evaluation per layer, $\approx (2n + 2) P$ | $\approx (2n + 2) F / B$ (negligible, independent of batch size) | yes | every layer $\sigma$ (soft; hinge form only above $k$) |

**Reading the table.**

- Relative to the $6F$ reference, the gradient penalty adds about 115% to 150%, the segment and random variants about 100%, the adversarial variant about 133%, and the endpoint variant, spectral normalization, and spectral norm regularization almost nothing.
- The gradient penalty is also the only method that must run uncompiled with a compiled critic, so its real overhead is larger by the speedup that compilation gives the rest of the step.
- Memory follows the same order. The gradient penalty keeps the recorded backward graph alive until `loss.backward()`. The finite-difference variants keep the activations of their extra forward passes. The endpoint variant, spectral normalization, and spectral norm regularization keep nothing beyond $O(P)$.
- Cost and strength trade against each other. The cheap methods constrain the weights (spectral normalization and regularization) or an average slope (endpoint). The expensive ones measure slopes at sample points, and the adversarial variant is the only finite-difference variant that approximates the gradient norm itself.

## 7. Tests

**(a) Baseline regression tests, written and green before any edits.** New `tests/loss/test_wasserstein_gan_regression.py` freezes `gradient_penalty_lip` and `gradient_penalty_opt` values and critic parameter gradients for a small MLP critic with fixed seeds, with and without `y_data`. It follows the tolerance approach of `tests/opt/test_train_single_process_regression.py`, which also must stay green unchanged: its `_d_reg_fn` declares no opt-in keywords, so it exercises the unchanged loop path.

**(b) Unit tests, `tests/loss/test_gradient_penalty_lip_fd.py`.**

- Linear critic $D(x) = w^\top x$: segment and endpoint quotients equal $|w^\top u|$ exactly; the adversarial quotient equals $\|w\|$ after one power step; the random quotient averages to about $\|w\| / \sqrt{d}$ within a statistical tolerance.
- Each penalty is 0 when $\|w\| \le k$ and positive otherwise; `one_sided=False` penalizes $\|w\| < k$.
- Identical pairs ($x_a = x_b$) give a finite penalty and finite gradients (`min_dist` and the zero-difference norm backward).
- A single broadcast `x_gen` sample and a full batch both work.
- Compiled critic (`aot_eager` backend, fixture shared with `tests/loss/test_wasserstein_gan.py`): each variant trains for a few steps without `eager`, and the compile counter shows no recompile after the first step.

**(c) Loop tests, `tests/opt/test_train_gan_regularizer_kwargs.py`.**

- A regularizer that declares all three opt-in keywords receives full-batch tensors in `float32` whose values match the loss's critic outputs.
- A regularizer declaring only some keywords receives only those.
- A closure with the fixed signature used by `fhn_gan` and `mops_gan` still runs.
- A `functools.partial` regularizer and one with `**kwargs` are handled.

**(d) Ship gate: `test_gradient_penalty_lip_fd_adversarial_compiled_ddp` in `tests/opt/test_train_gan_distributed.py`.** Two CPU ranks with the gloo backend (GPUs hidden) train a DDP-wrapped critic with a compiled `forward` using `gradient_penalty_lip_fd_adversarial` through `train_epochs`. The test asserts that training finishes without a DDP reducer error and that parameters are identical across ranks. This is the riskiest path: an extra input-gradient backward through a compiled critic inside a DDP training step.

**(e) Unit tests, `tests/loss/test_spectral_norm_regularizer.py`.**

- After warm-up, $\sigma_l$ of a `Linear` and a `Conv2d` layer matches `torch.linalg.matrix_norm` of the reshaped weight (`ord=2`) within a tolerance.
- The parameter gradient equals $\lambda \sigma_l u_l v_l^\top$ with $u_l, v_l$ from `torch.linalg.svd`, for the published form, and $\lambda \, \mathrm{relu}(\sigma_l - k) \, u_l v_l^\top$ for the hinge form.
- The hinge form gives 0 and zero gradients when all $\sigma_l \le k$.
- Layers wrapped with `parametrizations.spectral_norm` are skipped; a DDP-wrapped network is unwrapped.
- The state is recreated after a device or dtype change (`net.double()`).
- An instance used as `d_reg_fn` in `train_epochs` with a compiled critic (`aot_eager` backend) trains without `eager`, and `dlog` contains `sn_max` and `sn_mean`.
- Two regularizers with the same `seed` produce identical $u_l$ after warm-up, which is the property DDP ranks rely on.

## 11. Risks and edge cases

- Finite-difference penalties bound the Lipschitz constant from below, so critics trained with them can be steeper than with a gradient penalty. The regularization weight may need retuning when switching; the usage doc will say so.
- `radius` and `xi` are absolute input distances and depend on data scale. Defaults assume roughly standardized data.
- Segment pairs with $t_a \approx t_b$ give a quotient that is a directional derivative estimate with rounding error in both numerator and denominator; `min_dist` bounds the denominator only.
- The endpoint variant reuses `bfloat16` outputs under autocast; the cast to `float32` does not recover the lost precision of the numerator.
- The adversarial direction search bypasses DDP through `unwrap_net`. If a future DDP setting needs every forward to go through the wrapper, the ship-gate test will catch it.
- Changing batch sizes between calls recompiles a compiled critic; all variants use the batch shape of the loss terms to avoid this.
- The signature check for opt-in keywords cannot see through wrappers that hide their signature (for example a plain `lambda *args, **kwargs`); such a wrapper accepts `**kwargs` and therefore receives all keywords, which is safe.
- Spectral norm regularization with one power-iteration step per call relies on the weights changing slowly between steps, as spectral normalization does. After a large learning-rate jump, $\sigma_l$ lags behind for a few steps. `n_power_iterations` raises the accuracy at negligible cost.
- The published form (`max_norm=None`) shrinks every layer and can make the critic too flat, the spectrum collapse observed by Liu et al. 2019. The usage doc recommends the hinge form with `max_norm=1.0` for Lipschitz control.
- Per-layer penalties bound $\prod_l \sigma_l$ only if every layer is covered. Layers outside `WEIGHTED_LAYER_COMPATIBLE_TYPES`, such as the projections inside `nn.MultiheadAttention` (bare parameters), are not penalized.
- The regularizer's state is keyed by qualified module name. Renaming or restructuring the critic between calls drops the old entries and warms up new ones, which is correct but repeats the warm-up cost once.
- The cost figures in Part D are rule-of-thumb estimates. The profiler measurement in Section 9 may show different ratios, in particular for the gradient penalty's double backward, whose cost depends on the operators in the critic.
