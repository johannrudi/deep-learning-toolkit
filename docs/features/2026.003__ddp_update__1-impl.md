# Implementation: DDP Update in `dlk/opt/distributed.py`

## Context

The DDP feature landed per [2026.002__ddp__1-plan](2026.002__ddp__1-plan.md). This update reworks `dlk/opt/distributed.py` against **torch >= 2.11**, extends the tests, and fixes four problems:

1. **Device selection was CUDA-only.** The code branched on `torch.cuda.is_available()`, hard-coded the `nccl`/`gloo` backend pair, and named devices `cuda:{local_rank}`. It now uses the `torch.accelerator` API: XPU devices work without code changes, and MPS is treated as a gloo device instead of a per-process GPU (section 3).
2. **CPU oversubscription was invisible.** `DistributedContext` reported neither how many ranks share a node nor the thread count each rank runs with, so a log could not show that four ranks on one node each used all of its cores. The context now carries `local_world_size` and `num_threads`. Both are reports; thread control stays with `OMP_NUM_THREADS` (section 2).
3. **A dead rank stalled the survivors.** `finalize()` entered a barrier before destroying the process group. A crashed rank never reaches the barrier, so the surviving ranks waited out the full collective timeout (1800 s by default) instead of exiting. The new `session` context manager skips the barrier on the error path (section 4).
4. **The silent DDP failures had no check.** Replicas that drift apart and ranks that train on identical samples both leave a run that looks healthy and learns at single-process quality. `check_net_replica_drift` and `check_batch_ranks_differ` detect them (section 6).

**Scope:** `dlk/opt/distributed.py` and `tests/opt/`. The train loops (`train.py`, `train_gan.py`, `train_diffusion.py`) still call `initialize`/`finalize`; see [Open items](#open-items).

## Nomenclature

Additions to the plan's list:

- **`local_world_size`**: number of processes on this node; `world_size` counts across all nodes. torchrun exports it as `LOCAL_WORLD_SIZE`; under Slurm it must be derived.
- **intra-op threads**: the CPU threads torch uses inside one operator, controlled by `OMP_NUM_THREADS`.
- **accelerator API** (`torch.accelerator`): vendor-neutral access to the current accelerator (`cuda`, `xpu`, `mps`).
- **eager communicator init**: passing `device_id=` to `init_process_group` binds the communicator to a device at startup instead of at the first collective, which removes a class of NCCL hangs and spares `barrier()` from guessing a device.
- **replica drift**: elementwise divergence between the model copies held by different ranks; zero in a correct DDP run.

## 1. Launcher environment and `local_world_size`

`_read_launcher_environment()` returns `(rank, local_rank, world_size, local_world_size)`, or `None` for a single-process run.

- **torchrun**: `LOCAL_WORLD_SIZE` is read with a `WORLD_SIZE` default, so a manual `env://` launch that sets only `RANK` and `WORLD_SIZE` works.
- **Slurm**: `_read_slurm_local_world_size` derives the value, and all four variables are written back into `os.environ` so that `init_process_group("env://")` finds them.

Two Slurm variables carry per-node task counts:

| Variable | Set when | Meaning |
|---|---|---|
| `SLURM_NTASKS_PER_NODE` | the job passed `--ntasks-per-node` | requested count |
| `SLURM_TASKS_PER_NODE` | always | allocated count, per node |

`sbatch --nodes=2 --ntasks=8` leaves the first unset and sets the second to `"4(x2)"`, so both must be read. Resolution order: `SLURM_NTASKS_PER_NODE`, then `SLURM_TASKS_PER_NODE` indexed by `SLURM_NODEID`, then `world_size`. `_expand_slurm_tasks_per_node` expands the compressed format (`"2(x3),1"` becomes `[2, 2, 2, 1]`) and returns `[]` for a value that does not parse, which falls through to the next fallback instead of raising. Indexing by `SLURM_NODEID` keeps heterogeneous allocations correct. The final fallback is `world_size` rather than `1` because over-reporting the node's share flags oversubscription while under-reporting hides it.

## 2. Intra-op threads stay with `OMP_NUM_THREADS`

`initialize` reads `torch.get_num_threads()` once, stores it as `DistributedContext.num_threads`, and prints it in the initialization log line. The module never calls `torch.set_num_threads`: `OMP_NUM_THREADS` is the established control for intra-op threads, and a toolkit path that silently overrides it cannot be guessed by anyone debugging a slow run. The log line makes oversubscription visible (`local_world_size` ranks each reporting the node's full core count); the fix belongs in the launch command.

One consequence: torchrun exports `OMP_NUM_THREADS=1` when the variable is unset, and that value now stands. Sizing the variable per launcher is covered in [2026.003__ddp_update__2-usage](2026.003__ddp_update__2-usage.md).

An earlier draft resolved a thread count itself (explicit argument, then `SLURM_CPUS_PER_TASK`, then an even split of the affinity mask) and applied it with `torch.set_num_threads`. It was dropped because it made the toolkit a second, hidden owner of a knob the environment already owns.

## 3. Device selection and backend

`_select_device(local_rank)` binds the process to one accelerator:

```python
accel = torch.accelerator.current_accelerator(check_available=True)
if accel is None:
    return torch.device("cpu")
# ... bounds check ...
torch.accelerator.set_device_index(local_rank)
return torch.device(accel.type, local_rank)
```

When `local_rank >= torch.accelerator.device_count()`, it raises a `RuntimeError` naming the rank, the visible device count, and the fix (start one process per device, or widen the device mask). This happens when `--nproc-per-node` exceeds the devices per node or `CUDA_VISIBLE_DEVICES` is mis-set; previously it surfaced as a raw torch error at an unrelated line.

The backend comes from `torch.distributed.get_default_backend_for_device(device)`: cuda maps to nccl, xpu to xccl, cpu and mps to gloo.

The module constant `_COMMUNICATOR_DEVICE_TYPES = ("cuda", "xpu")` lists the device types whose backend binds one device per process. It gates the only two device-binding arguments: `device_id=` in `init_process_group` and `device_ids=` in `wrap_net`. The earlier condition "not CPU" was wrong for MPS, which runs collectives through gloo and accepts neither argument. `init_method="env://"` is no longer passed explicitly; omitting it selects the same default.

## 4. Lifecycle: `session` and `finalize(synchronize)`

`session` wraps `initialize` and `finalize` so the process group is destroyed on every path out of the block:

```python
try:
    yield ctx
except BaseException:
    finalize(synchronize=False)
    raise
else:
    finalize()
```

`finalize(synchronize=False)` skips the barrier before `destroy_process_group`. A barrier is a collective every rank must enter, and a crashed rank never will, so barriering on the error path costs the survivors the full `timeout_seconds` before they can exit. The normal path keeps the barrier, and `finalize()` keeps `synchronize=True` as its default for direct callers.

## 5. `sampler_create` takes a context

`sampler_create` gained a second parameter `ctx`, and `seed` was renamed to `base_seed` to match `seed_random_generators` and to discourage passing a rank-offset seed, which desynchronizes the shuffle across ranks.

| Call | Result |
|---|---|
| `ctx=None`, no process group | `None`; the caller keeps its plain `shuffle=` path |
| `ctx=None`, process group live | sampler reading rank and world size from the process group |
| `ctx` given | always a sampler, sharding per `ctx.rank` and `ctx.world_size` |
| `ctx.world_size > 1`, no process group | `RuntimeError` |

A single-process `ctx` yields a one-replica sampler because `DistributedSampler` queries the process group only when `num_replicas` and `rank` are `None`. The `RuntimeError` catches a real setup error: sharding a dataset among ranks that never exchange gradients silently trains every rank on a fraction of the data.

## 6. Debugging collectives

Both functions are collectives (every rank must call them or the run deadlocks) and debugging aids rather than training-loop code.

`check_net_replica_drift(net, include_buffers=False)` broadcasts rank 0's tensors and reduces the largest elementwise difference with `ReduceOp.MAX`, so every rank returns the same float. `0.0` means identical replicas; anything else means they diverged, typically from a rank-dependent initialization or an optimizer step taken outside DDP's gradient synchronization. It unwraps DDP itself, compares tensor by tensor to avoid allocating a flattened copy of the model, and casts to `float64` so that bf16/fp16 parameters do not round small drift away. `include_buffers=True` adds buffers such as batch-norm running statistics. Returns `0.0` when not distributed or when the model has no tensors.

`check_batch_ranks_differ(batch)` all-gathers one float64 checksum per rank and returns whether all are distinct. Identical checksums mean the ranks train on the same samples, which reduces a `world_size`-way run to `world_size` copies of one gradient; the usual cause is a dataloader built without a `DistributedSampler`. A checksum can collide, so `False` is conclusive and `True` is strong evidence. Returns `True` when not distributed.

## 7. Tests

`tests/opt/test_distributed.py` grew from 8 to 30 test functions (`tests/opt`: 16 to 38 passing). `tests/opt/ddp_test_utils.py` gained `set_launcher_environment(rank, world_size, port, slurm_style=False)`, split out of `init_worker`, which now delegates to it; a test can set launcher variables and then drive `session()` or `initialize()` itself.

| Area | Tests |
|---|---|
| Slurm parsing | `_expand_slurm_tasks_per_node` (compressed, plain, unparseable); `_read_slurm_local_world_size` across all three fallback levels |
| Threads | `initialize` records the ambient `torch.get_num_threads()` without changing it, single- and two-process |
| Launcher env | `None` without variables; torchrun with and without `LOCAL_WORLD_SIZE`; Slurm tuple and environment write-back |
| `session` | yields a usable context and destroys the group, on the normal and the exception path, single- and two-process |
| `sampler_create` | `None` without ctx; one-replica sampler for a single-process ctx; `RuntimeError` for a multi-process ctx without a group; disjoint shards across two ranks |
| Debug collectives | defaults when not distributed; drift `0.0` when synchronized and exactly the injected `0.25` after a perturbation; buffer drift visible only with `include_buffers=True`; batches `True` when sampler-sharded, `False` when identical |

Two details to preserve when editing these tests:

- The drift worker calls `torch.manual_seed(rank)` before constructing the model, so the replicas genuinely differ until DDP's wrap-time broadcast. Without it, the `drift == 0.0` assertion passes vacuously.
- `monkeypatch.delenv(name, raising=False)` on an already-absent variable records no undo action. The Slurm path then writes `RANK`/`LOCAL_RANK`/`WORLD_SIZE`/`LOCAL_WORLD_SIZE` straight into `os.environ`, teardown restores nothing, and the leaked values make a later test attempt a real `init_process_group` without `MASTER_ADDR`. `test_read_launcher_environment_slurm_writes_back_environment` pops the four keys in a `try/finally`; any test that lets code under test write an initially-absent variable needs the same pattern.

## Breaking changes

| Change | Migration |
|---|---|
| `sampler_create(seed=...)` renamed to `base_seed=` | rename the keyword; the value is unchanged (the base seed, identical on all ranks) |
| `DistributedContext` gained `local_world_size`, `num_threads` | affects only code constructing one directly; field order is `rank, local_rank, world_size, local_world_size, device, num_threads, is_main, is_distributed` |

`finalize(synchronize)` and `session` are additive; every other signature is unchanged.

## Verification

```
uv run --no-sync pytest tests -q          # 121 passed
uv run --no-sync basedpyright dlk tests   # 0 errors, 0 warnings, 0 notes
make format-check && make compile         # clean
```

All tests run on CPU with the gloo backend, two processes via `mp.spawn`. **No GPU/NCCL verification has been done for this update**: the accelerator API, `device_id=` eager init, and the `_COMMUNICATOR_DEVICE_TYPES` gating are exercised only on the CPU path so far.
