# Lipschitz Regularization of WGAN Critics: Gradient Penalties, Finite-Difference Penalties, and Spectral Norm Regularization

A Wasserstein GAN critic needs a bounded **Lipschitz constant**, the largest slope $|D(x) - D(x')| / \|x - x'\|$ the critic attains. `dlk/loss/gradient_penalty.py` offers five penalties that keep it in check: the autograd `gradient_penalty` and four finite-difference penalties, `gradient_penalty_fd_segment`, `gradient_penalty_fd_endpoint`, `gradient_penalty_fd_adversarial`, and `gradient_penalty_fd_random`. The finite-difference penalties only evaluate the critic, so they work with a compiled critic as is. `SpectralNormRegularizer` in `dlk/loss/spectral_penalty.py` penalizes the weights' spectral norms instead, a loss-based alternative to spectral normalization that leaves the critic's architecture unchanged. See `docs/features/2026.008__gradient_penalties__2-revision.md` for the mathematics.

**All five penalties share one form and one signature.** Each estimates a per-sample squared slope $s^2$, penalizes it with the same one- or two-sided formula, takes the same arguments `lip`, `eps`, `one_sided`, and `one_sided_nonlinearity`, and has the signature `(d_net, x_gen, x_data, y_data, ...)` of `dlk.opt.train_gan.DiscriminatorRegularizerFn`. Switching penalties is a change of function name.

## Choosing a method

| Method | Compiled critic, no `eager` | Extra cost per critic step (estimate / measured CPU) | What is constrained |
|---|---|---|---|
| `gradient_penalty` | No: needs `eager=True`, and then the penalty itself runs uncompiled | 7F-9F / 5.75F | gradient norm at an interpolate |
| `gradient_penalty_fd_segment` | Yes | ~6F / 5.63F | slope along a real-to-generated segment (lower bound) |
| `gradient_penalty_fd_random` (baseline) | Yes | ~6F / 5.61F | slope in a random direction, ~1/sqrt(d) of the gradient norm |
| `gradient_penalty_fd_adversarial` | Yes (one extra compile) | ~8F / 7.53F | slope in the steepest found direction, closest to the gradient norm |
| `gradient_penalty_fd_endpoint` | Yes | ~0 / 0.04F | average slope between one real and one generated sample (loosest bound) |
| Spectral normalization (`enable_spectral_norm=True` in `MLPResNet`/`ConvResNet`) | Untested (see `docs/features/2026.007__conv_spectral_norm__2-usage.md`) | negligible / 0.39F | every layer's sigma <= 1 (hard, reshaped norm for convolutions) |
| `SpectralNormRegularizer` as `d_reg_fn` | Yes: never calls the critic | negligible / <= 0.1F | every layer's sigma (soft; hinge form only above `max_norm`) |

`F` is one critic forward pass. The "Yes" entries are verified with `aot_eager` and CPU inductor; CUDA inductor, where the original donated-buffer error appeared, is not yet verified. Measured: CPU, one thread, uncompiled, conditional MLP critic `Linear(d+d_y, H) -> Tanh -> Linear(H, H) -> Tanh -> Linear(H, 1)` with `H=1024`, `B=1024` (`logs/impl/2026.008/step-10/cost_results.md`, Table 2). At `H=256, B=256`, the gradient penalty, segment, and random are within noise of each other, roughly 5F (+/-0.3F; CPU, 1 thread). Compiling the critic (inductor, CPU, H=1024, B=1024, 1 thread) changes each measured method's extra cost by at most about 3% in wall time (spectral normalization not measured compiled), except the adversarial variant, about 11% more compiled. The choice between one- and two-sided does not change the cost.

Recommendation:

- Critic is compiled and you want something close to the gradient penalty: `gradient_penalty_fd_adversarial`, or `gradient_penalty_fd_segment` if the adversarial variant's extra cost is not worth it.
- Cheapest: `gradient_penalty_fd_endpoint` (reuses the loss's own critic outputs) or `SpectralNormRegularizer(max_norm=1.0)` (never calls the critic); prefer spectral normalization (`enable_spectral_norm=True`) over either if you want a hard architectural bound instead of a loss term.
- `gradient_penalty_fd_random` is an ablation baseline only, not a recommended penalty; in high input dimension it sees only a small fraction of the critic's slope.

## The penalty form

Each penalty computes a per-sample squared slope $s^2$: `gradient_penalty` uses the squared gradient norm $\|\nabla_{(x, y)} D(\hat{x}, y)\|^2$ at a random interpolate $\hat{x}$ between a real and a generated sample, and the finite-difference penalties use the squared **difference quotient** $q^2 = \|D(x_a) - D(x_b)\|^2 / \max(\|x_a - x_b\|^2, \delta^2)$ of a pair of points, where the variants differ in how they choose the pair. With the target $k$ (`lip`) and a small $\varepsilon$ (`eps`), the penalty is

$$\mathcal{R}_\mathrm{one} = E[\phi(s^2 + \varepsilon - k^2)] \quad (\texttt{one\_sided=True}), \qquad \mathcal{R}_\mathrm{two} = E[(\sqrt{s^2 + \varepsilon} - k)^2] \quad (\texttt{one\_sided=False}).$$

The **one-sided** penalty acts on slopes above $k$. Its nonlinearity $\phi$ (`one_sided_nonlinearity`) defaults to a sharp softplus, $\mathrm{softplus}(10 z) / 10$, a smooth relu that is tiny but positive below the threshold ($\ln 2 / 10 \approx 0.069$ exactly at it); pass `torch.nn.functional.relu` for a penalty that is exactly zero below the target. Here $\varepsilon$ is a margin that tightens the threshold to $s^2 \le k^2 - \varepsilon$.

The **two-sided** penalty pulls the slope toward $k$ from both sides; with $k = 1$ and `gradient_penalty` it is the WGAN-GP penalty. Here $\varepsilon$ guards the square root, whose derivative is infinite at a zero slope, so it must be positive.

## Closure examples

A regularizer passed as `d_reg_fn` must match `dlk.opt.train_gan.DiscriminatorRegularizerFn`. The loop calls it with `d_net, x_gen, x_data, y_data` and the keywords `dlog`, `d_outputs_gen`, and `d_outputs_data`. A closure that scales a penalty by a regularization weight forwards all of them:

```python
from dlk.loss.gradient_penalty import gradient_penalty_fd_segment

reg_param = 10.0

def d_reg_fn(d_net, x_gen, x_data, y_data, *, dlog=None, d_outputs_gen=None, d_outputs_data=None):
    return reg_param * gradient_penalty_fd_segment(
        d_net,
        x_gen,
        x_data,
        y_data,
        d_outputs_gen=d_outputs_gen,
        d_outputs_data=d_outputs_data,
        dlog=dlog,
    )
```

The same closure works for every penalty: swap the function name and the import. `reg_param` is an example weight; tune it per "Tuning". Penalty arguments such as `lip` or `one_sided=False` go into the call.

- `gradient_penalty_fd_endpoint` reads its numerator from `d_outputs_gen` and `d_outputs_data`, the critic outputs the loss already computed, and ignores `d_net` and `y_data`. It raises `ValueError` if either output is `None`, which the loop never passes.
- The other penalties ignore `d_outputs_gen` and `d_outputs_data`.
- `gradient_penalty` with a compiled critic needs `eager=True` in the call (see "Fixing common issues").
- `device`, the device for random draws, is optional on every penalty and defaults to `x_data`'s device.

`SpectralNormRegularizer.__call__` already matches `DiscriminatorRegularizerFn`, so an instance is a `d_reg_fn` with no closure at all:

```python
from dlk.loss.spectral_penalty import SpectralNormRegularizer

d_reg_fn = SpectralNormRegularizer(penalty_weight=reg_param, max_norm=1.0)
```

## Tuning

- `lip` (all five penalties; default `1.0`): target Lipschitz constant `k`. Keep it at `1.0` unless the critic is meant to be `k`-Lipschitz for a different `k`.
- `one_sided` (all five penalties; default `True`): `False` selects the two-sided form. The two-sided form fits `gradient_penalty` and the adversarial variant, whose slope estimates approximate the gradient norm, and the segment and endpoint variants, whose pairs lie along the direction in which the optimal critic has slope 1. For the random variant it has no natural target, because its quotient sees only a fraction of the slope.
- `one_sided_nonlinearity` (all five penalties; default sharp softplus): the $\phi$ of the one-sided form; any elementwise function of a tensor works, for example `torch.nn.functional.relu`.
- `eps` (all five penalties; default `1e-6`): a margin for the one-sided form, a square-root guard for the two-sided form. It must be `>= 0`, and `> 0` when `one_sided=False`.
- `min_dist` (finite-difference variants; default `1e-6`): floor on the pair distance, guarding the difference quotient against division by zero. It must be `> 0`.
- `radius` (random, adversarial; default `1e-1`) and `xi` (adversarial only, default `1e-2`): absolute distances in input units, not fractions of the data's scale. The defaults assume roughly standardized data; rescale them if your inputs are not.
- `penalty_weight` (`SpectralNormRegularizer`, default `1.0`): the `lambda` multiplying the penalty.
- `max_norm` (`SpectralNormRegularizer`, default `None`): `None` gives the published form (Yoshida and Miyato 2017), which shrinks every layer's sigma, including layers already below 1, a known route to the spectrum collapse Liu et al. 2019 tie to mode collapse. For Lipschitz control, prefer the hinge form `max_norm=1.0`, which only pushes layers above the target.
- `n_power_iterations` (`SpectralNormRegularizer`, default `1`): power-iteration steps per call once a layer's `u_l` is warmed up; raise it if the weights change quickly between steps (large learning rate).
- `n_warmup_iterations` (`SpectralNormRegularizer`, default `15`): steps used the first time a layer is seen, or after a shape/device/dtype change.
- `seed` (`SpectralNormRegularizer`, default `0`): seeds the generator each layer's initial `u_l` is drawn from; matching seeds across DDP ranks keep their `u_l` identical after warm-up.

Finite-difference penalties bound the Lipschitz constant from below, more loosely than the gradient penalty at the same points (among the segment-based variants, endpoint is loosest; adversarial is closest to the gradient norm; random sees only about 1/sqrt(d) of it). Switching from `gradient_penalty` to a finite-difference variant at the same regularization weight can therefore under-constrain the critic; retune the weight rather than assuming parity.

## Logged values

Each regularizer writes to the `dlog` dictionary it is called with; the loop copies those keys into the epoch log with a `d_pre_`/`d_post_` prefix (the last of the `d_opt_pre`/`d_opt_post` discriminator steps run before/after the generator update each batch; with `d_opt_post=0`, no `d_post_` values are written) and a `_mean`/`_std` suffix (per-epoch statistics). A tag no regularizer writes still appears in the log, reading `0.0`.

| Regularizer | `dlog` key | Epoch log names (pre-step; post-step mirrors with `d_post_`) |
|---|---|---|
| `gradient_penalty` | `grad_norm` (mean gradient norm) | `d_pre_grad_norm_mean`, `d_pre_grad_norm_std` |
| Any finite-difference variant | `grad_fd_norm` (mean difference quotient $q$) | `d_pre_grad_fd_norm_mean`, `d_pre_grad_fd_norm_std` |
| `SpectralNormRegularizer` | `spectral_norm` (mean of the layers' sigmas; only if at least one layer qualifies) | `d_pre_spectral_norm_mean`, `d_pre_spectral_norm_std` |

A regularizer can log only keys that appear, with the `d_pre_`/`d_post_` prefix, in `dlk.opt.train_gan.MONITOR_BASENAMES`; the three keys above are registered there.

## Critic outputs and precision

`_train_step_discriminator` (`dlk/opt/train_gan.py`) always computes `d_outputs_gen` and `d_outputs_data` for the Wasserstein loss, and always passes them to `d_reg_fn` as keywords; every regularizer must accept both, even if it ignores them (a `None` default is enough).

By default, both are `.float()` casts of the loss's own outputs, so they are `float32` even under `bfloat16` autocast (the cast does not restore precision lost under autocast; see "Things worth knowing"), and `d_reg_fn` itself runs outside the forward pass's autocast context, so any fresh `d_net` call a regularizer makes runs in full precision too. The cast keeps the autograd connection: the regularizer's gradient flows through the same critic graph as `d_loss` in the single `loss.backward()`.

Pass `autocast_d_reg_fn=True` to `train_epochs`/`train_batches` to opt a regularizer into the forward pass's autocast policy instead: `d_outputs_gen`/`d_outputs_data` then keep whatever dtype autocast produced, uncast, and `d_reg_fn` itself runs inside the same autocast context, so any fresh `d_net` call it makes is mixed-precision too. This is a training-loop-wide setting, not per-regularizer, so only combine it with regularizers that tolerate the loss's autocast dtype; the finite-difference variants are numerically sensitive to reduced precision (see "Things worth knowing") and should stay at the default `autocast_d_reg_fn=False`.

Declare both keywords with a `None` default; required keyword-only parameters fail `basedpyright` against `DiscriminatorRegularizerFn` (see "Fixing common issues"). If your own regularizer code uses the outputs, narrow them with an `assert d_outputs_gen is not None`.

## Things worth knowing

- **No dropout in a critic trained with a finite-difference penalty.** Each critic call draws a fresh dropout mask, so the quotient's numerator measures mask noise, not slope. Measured with an MLP critic and `Dropout(0.1)` (mean quotient, eval mode vs. train mode): adversarial 0.16 vs. 0.98, random 0.07 vs. 0.88, segment 0.07 vs. 1.23. The gradient penalty, a single forward pass, does not have this failure mode.
- **Random and adversarial run in full precision.** Small perturbations (`radius`, `xi`) fall within a few `bfloat16` ulps of the critic's outputs under autocast; the training loop evaluates `d_reg_fn` outside autocast by default, so this only matters with `autocast_d_reg_fn=True` or if you call these functions yourself under an explicit autocast context. This does not help the endpoint variant: its numerator is the loss's own `bfloat16`-computed outputs cast to `float32` after the fact, and that cast does not restore the lost precision.
- **The two-sided form is steep near a zero slope.** Its square root has derivative $1 / (2 \sqrt{s^2 + \varepsilon})$, about 500 at $s = 0$ with the default `eps`. Raise `eps` if a critic that starts nearly flat produces large penalty gradients.
- **One `SpectralNormRegularizer` instance per network.** Its power-iteration state is keyed by qualified module name only, so two networks with matching layer names sharing one instance would corrupt each other's `u_l`. The state is not part of any `state_dict`; after a checkpoint restart, warm-up (`n_warmup_iterations` steps) re-converges it from scratch.
- **Not every layer is covered.** `SpectralNormRegularizer` and spectral normalization both act on `dlk.nets.utils.WEIGHTED_LAYER_COMPATIBLE_TYPES` (`Linear`, `Conv1d/2d/3d`, `ConvTranspose1d/2d/3d`). Bare-parameter layers such as `nn.MultiheadAttention`'s internal projections are not penalized, so the product-of-sigmas bound does not cover them.
- **`LayerNorm`, self-attention, and dropout break the product bound** that per-layer sigma control relies on, independent of which mechanism (normalization or regularization) enforces the per-layer bound.
- **Legacy `torch.nn.utils.spectral_norm` layers are not skipped.** `SpectralNormRegularizer` only detects `torch.nn.utils.parametrizations.spectral_norm`, so a legacy-wrapped layer is not skipped and gets penalized on its already-normalized weight `W / sigma(W)`.
- **The adversarial variant compiles a second graph on its first step**, because its direction search calls the critic with an input that requires grad, a shape of call the rest of the loop does not make; there is no recompile afterward.

## Fixing common issues

**`KeyError: 'd_pre_my_custom_tag'` (or `'d_post_...'`) from `monitor.batch_update`.** A custom regularizer logged a `dlog` key that is not in `MONITOR_BASENAMES`. Use `grad_norm`, `grad_fd_norm`, or `spectral_norm` (see "Logged values"), or add your tag to `MONITOR_BASENAMES` in `dlk/opt/train_gan.py`.

**`TypeError: ... got an unexpected keyword argument 'd_outputs_gen'` (or `'d_outputs_data'`).** The loop always calls `d_reg_fn` with both keywords; a regularizer that declares neither, or only one, and has no `**kwargs`, does not conform to `DiscriminatorRegularizerFn`. Add both parameters, with `None` defaults, even if unused (see "Closure examples" and `SpectralNormRegularizer.__call__`).

**`Extra parameter "d_outputs_gen"` (`reportAssignmentType`) from `basedpyright`.** The closure declared the keywords as required, not defaulted. `basedpyright` reports:

```text
error: Type "(...) -> Tensor" is not assignable to declared type "DiscriminatorRegularizerFn"
    Extra parameter "d_outputs_gen"
    Extra parameter "d_outputs_data" (reportAssignmentType)
```

Give them `None` defaults (see "Critic outputs and precision").

**`ValueError: eps must be > 0 for the two-sided penalty, ...`.** `one_sided=False` takes a square root of $s^2 + \varepsilon$, which needs a positive `eps`. Keep the default `1e-6` or pass another positive value.

**`RuntimeError: ... does not currently support double backward` (or a donated-buffers message) with a compiled critic.** `gradient_penalty` needs a double backward, which `torch.compile`'s AOTAutograd does not support. Either pass `eager=True` (the penalty then runs uncompiled) or switch to a finite-difference variant, none of which needs `eager`.
