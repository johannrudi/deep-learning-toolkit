# Plan: DDP Support for `dlk`

## Context

`dlk/opt` provides single-process training loops (`train.py`, `train_gan.py`, `train_diffusion.py`) used by application codes such as `../neural_nets/mops_gan/run.py`. The goal is to extend these to distributed data-parallel training on HPC systems (CPU clusters and NVIDIA GPU nodes) so that applications can go distributed with small and obvious changes. Before this feature there is zero distributed code in the toolkit, no checkpoint-load function, and no tests for `dlk/opt`.

**Launch method (research conclusion):** `torchrun` is PyTorch's native, maintained launcher (successor of the deprecated `torch.distributed.launch`); `mp.spawn` is recommended for debugging only. On Slurm, `srun torchrun ...` covers multi-node. Decision: support torchrun as primary, plus a minimal Slurm fallback that derives ranks from `SLURM_PROCID`/`SLURM_LOCALID`/`SLURM_NTASKS` when torchrun env vars are absent but `MASTER_ADDR`/`MASTER_PORT` are exported — so plain `srun python run.py` also works.

**Settled design decisions:**

- torchrun + Slurm-env fallback for process launch.
- Loss statistics all-reduced at epoch level (exact global mean/std, one tiny collective per epoch).
- Scope: all loops (`train.py`, `train_gan.py`; `train_diffusion.py` inherits) + DDP-aware profiling in `profiler.py`.
- Validation runs on rank 0 only, with the unwrapped model; existing validation code works unchanged.

**Core principle:** zero signature changes to `train_epochs`/`train_batches`. All rank-awareness is internal and auto-detected via `torch.distributed.is_initialized()`. Consequences: the mirrored Protocols in `profiler.py` need no changes, `train_diffusion` inherits DDP for free, and single-process behavior is provably unchanged (every helper degrades to a no-op/passthrough).

## Nomenclature

- **DDP (`DistributedDataParallel`)**: PyTorch wrapper replicating a model across processes; each process trains on a data shard, gradients are averaged automatically during `backward()`.
- **rank / local_rank / world_size**: global process index; process index within one node (= which GPU to use); total number of processes.
- **torchrun**: PyTorch's launcher; spawns one process per GPU/worker and sets `RANK`, `LOCAL_RANK`, `WORLD_SIZE`, `MASTER_ADDR`, `MASTER_PORT` env vars.
- **rendezvous**: how processes find each other at startup; `env://` means "read the env vars above".
- **process group / backend**: the communicator; **NCCL** = NVIDIA GPU backend, **gloo** = CPU backend.
- **collective**: operation all ranks must enter together (e.g. **all-reduce** = elementwise sum/average across ranks; **barrier** = wait for all ranks). A rank skipping a collective deadlocks the job.
- **`DistributedSampler`**: splits a dataset across ranks; needs `set_epoch(epoch)` each epoch to reshuffle (forgetting it is the classic silent DDP bug — same shuffle order every epoch).

## 1. New module `dlk/opt/distributed.py`

All building blocks; no imports from other `dlk.opt` modules (avoids cycles). Public API:

- `DistributedContext` (frozen dataclass): `rank`, `local_rank`, `world_size`, `device`, `is_main`, `is_distributed`.
- `initialize(backend=None, timeout_seconds=1800.0, logger=None) -> DistributedContext` — detection order: (1) torchrun env vars → `init_process_group("env://")`; (2) `SLURM_PROCID` + `MASTER_ADDR` set → populate env vars from Slurm, then `env://`; (3) neither → single-process context (rank 0, world 1, `is_distributed=False`), no process group. Backend auto: `nccl` if CUDA else `gloo`. On CUDA: `torch.cuda.set_device(local_rank)` **before** `init_process_group`.
- `finalize()` — barrier + `destroy_process_group`; no-op single-process.
- `is_distributed()`, `get_rank()`, `get_world_size()`, `is_main_process()`, `barrier()` — all safe no-ops/defaults single-process.
- `wrap_net(net, device, find_unused_parameters=False, broadcast_buffers=True, static_graph=False)` — returns `net` unchanged when not distributed; `device_ids=[device.index]` for CUDA, `None` for CPU.
- `unwrap_net(net)` — `net.module` if DDP-wrapped else `net`.
- `sampler_create(dataset, shuffle=True, seed=0, drop_last=False)` — `None` when not distributed (caller keeps its plain `shuffle=` path). `seed` must be the **base** seed, identical on all ranks.
- `sampler_set_epoch(dataloader, epoch_idx)` — duck-typed (`getattr(dataloader, "sampler", None)`, then `set_epoch` if present); safe no-op for plain loaders. Called inside the train loops so applications cannot forget it; the `DataLoaderType` Protocol stays unchanged.
- `seed_random_generators(base_seed, rank_offset=True) -> int` — seeds `random`/numpy/torch(.cuda) with `base_seed + rank`; returns effective seed.
- `all_reduce_sum_(values)` — in-place SUM all-reduce; no-op single-process.

## 2. `dlk/opt/utils.py`

- `tqdm_disable()`: also return `True` on non-main ranks (silences tqdm in both train loops in one place).
- `checkpoint_save()`: save `model.module.state_dict()` when the model is DDP-wrapped (isinstance check) so checkpoints never contain `module.`-prefixed keys.
- New `checkpoint_load(filepath, model, optimizer=None, map_location=None) -> int` (missing entirely today): `torch.load(..., map_location=map_location or "cpu", weights_only=True)`, load into `unwrap_net(model)`, defensively strip a leading `"module."` from keys, optionally restore optimizer state, return stored epoch. Under DDP every rank loads the same file with `map_location=ctx.device`, preferably before `wrap_net`.
- New `train_dlog_batch_all_reduce(dlog, tags, device=None)`: packs `{tag}_mean_n`, `{tag}_mean`, `{tag}_sq_mean` into one float64 tensor (on `device` for NCCL, CPU for gloo), SUM all-reduce, unpack. Called **before** `train_dlog_batch_finalize` (which divides by `mean_n`) → exact global mean/std. No-op single-process.

## 4. `dlk/opt/train_gan.py`

Mirror train.py: checkpoint-dir creation and saves rank-0-only; validation rank 0 + unwrapped nets; `sampler_set_epoch` after `epoch_initialize_fn`; throughput × world_size; `train_dlog_batch_all_reduce(batch_dlog, DLOG_BASENAMES, device)` before finalize.

**Required correctness fix** (`_train_step_discriminator`): replace `x_gen = g_net(y_data, z).detach()` with a `torch.no_grad()` forward. With grad enabled, a DDP-wrapped `g_net` forward arms the gradient reducer; since no backward reaches `g_net`, the next generator step fails with "Expected to have finished reduction in the prior iteration". Mathematically identical single-process.

GAN notes (encode in docstrings): both nets are wrapped independently by the caller; `find_unused_parameters=False` and `static_graph=False` (graph varies with `g_opt_freq`/`d_reg_fn`); `broadcast_buffers=False` recommended for `d_net` (2–3 discriminator forwards per batch each cost a buffer broadcast otherwise). Gradient penalty (`d_reg_fn`): inner `autograd.grad` is w.r.t. inputs only (no reducer hooks fire), single outer `backward()` fires hooks once — gated by a dedicated 2-process test before shipping.

## 5. `dlk/opt/train_diffusion.py`

Add a `sampler` property to `DataLoaderWrapper` (next to `batch_size`) delegating to `getattr(self.dataloader, "sampler", None)` so `sampler_set_epoch` reaches the inner `DistributedSampler`. `train_epochs` unchanged (delegates to `train.train_epochs`). Per-rank `torch.randn` draws in `transform` differ across ranks under rank-offset seeding — desired.

## 6. `dlk/opt/profiler.py` (DDP-aware profiling)

- Protocols `TrainEpochsFn`/`TrainBatchesFn`: **no edits needed** (no signature changes upstream); add a comment making the lockstep-mirror invariant explicit.
- `trace_handler`: rank-suffixed outputs when distributed — `table_prof_step_{N}_rank{r}.txt` / `trace_prof_step_{N}_rank{r}.json` written on **every** rank (per-rank Chrome traces are what shows NCCL/gloo comm ops, stragglers, backward/all-reduce overlap); `print(table)` main-rank-only. Single-process filenames byte-identical to before.
- Communication ops need no extra config: `ProfilerActivity.CUDA` (already selected) captures NCCL kernels; c10d collectives appear as CPU-side events in torch>=2. Keep `record_shapes=True` (annotates all-reduce bucket sizes). Gloo runs: collectives are CPU ops, captured under `ProfilerActivity.CPU` — `_select_profiler_activities` needs no functional change.
- Schedule interaction: `profile_train_epochs` steps per epoch — `sampler_set_epoch` now happens inside the loop, no interaction. `profile_train_batches` uses `max_batches=10`, rank-identical, and `DistributedSampler` pads to rank-equal length → early break is rank-synchronous, no hangs. Document `len(dataset) >= 10 * batch_size * world_size` for meaningful profiled batches, and that callers `wrap_net` the model before profiling (every rank runs the profile functions).

## 7. Application migration (mops_gan sketch — the "small and obvious" contract)

```python
from dlk.opt import distributed as dlk_dist

dist_ctx = dlk_dist.initialize()               # replaces device selection
device = dist_ctx.device
logging_set_up(save_dir / (f"{name}_rank{dist_ctx.rank}" if dist_ctx.is_distributed else name))
dlk_dist.seed_random_generators(random_seed)  # replaces manual seeding

net = dlk_dist.wrap_net(net, device)          # after each create_* factory
d_net = dlk_dist.wrap_net(d_net, device, broadcast_buffers=False)

# data.py create_dataloader: thread the sampler
sampler = dlk_dist.sampler_create(dataset, shuffle=shuffle, seed=base_seed)
# if sampler is not None: kwargs["sampler"] = sampler; kwargs["shuffle"] = False

# end of training: non-main ranks finalize and return; rank 0 predicts/evals/plots alone
dlk_dist.finalize()
```

Flag for the app (docs, not this repo): `multiprocessing_context="fork"` in dataloader kwargs is unsafe with CUDA under DDP (use `"spawn"` or `num_workers=0`); `num_workers` is per rank.

- `test_train_distributed.py` — 2-proc `train_epochs` with `DistributedSampler` + `checkpoint_epochs=1`: params bitwise-identical across ranks after training; exactly one timestamped checkpoint dir; `checkpoint_load` round-trip incl. a synthetic `module.`-prefixed state dict; reduced `loss_mean` identical on both ranks; `validation_fn` called only on rank 0 with a non-DDP module.

## 10. DDP-unrelated improvements observed (report only; decide separately)

1. `train.py` and `train_gan.py` duplicate the whole epoch-loop scaffold (checkpoint-dir creation, LR-scheduler step/logging, tqdm, throughput stats). Factoring shared helpers into `utils.py` would halve the DDP diff and prevent future drift.
2. `net.train()` is called per **batch** (`train.py:237`, `train_gan.py:448-449`); once per epoch before the batch loop suffices (validation may flip eval mode between epochs, so per-epoch, not once globally).
3. `loss.item()` per batch (`train.py:268`; the `dlog_item` items in `train_gan.py:331-336,384`) forces a GPU sync every batch; accumulating detached tensors and materializing at epoch end would remove the stalls.
4. `train_gan.py:251-263` throughput stats lack the `n_steps > 0`/`time_train > 0` guards that `train.py:177-178` has (division by zero), and both files log `samples/sec {x:g} sec` — wrong unit suffix. GAN "optimizer steps" also ignores `d_opt_pre`/`d_opt_post`/`g_opt_freq`.
5. `train_gan.train_batches`/`train_epochs` type `dataloader` as concrete `torch.utils.data.DataLoader` (lines 77, 392) instead of the `DataLoaderType` Protocol used by `train.py`.
6. `n_samples = n_steps * dataloader.batch_size` overcounts when `drop_last=False` leaves a short last batch.

## 13. Risks / edge cases

- `DistributedSampler` pads (repeats samples) so `len(dataloader)` is rank-equal — prevents hangs but slightly biases epoch metrics; `drop_last=True` on the sampler is the alternative (document, don't change).
- `max_batches` early break (`train.py:229`) is safe only because rank-identical; custom loaders must have rank-equal length (document in `DataLoaderType`).
- Log-file clobbering (`dlk/mgmt/log.py` `filemode="w"`): solved at app level via rank-suffixed basenames; the library never configures logging.
- NCCL: `set_device` before init; explicit timeout; `barrier()` before `destroy_process_group`.
- `torch.load` with `weights_only=True` in `checkpoint_load`.
- Test flakiness: free-port fixture, gloo-only in CI, generous spawn join timeouts.

## 14. Addendum: deviations and findings during implementation

Unforeseen issues encountered while executing the plan, and how they were resolved:

1. **`broadcast_buffers` deprecated in torch 2.13.** The real-torchrun smoke test surfaced a `FutureWarning`: DDP renames `broadcast_buffers` to `forward_sync_buffers`. `wrap_net` keeps its `broadcast_buffers` parameter (stable toolkit API across `torch>=2,<3`) and internally passes `forward_sync_buffers` when the installed DDP supports it (signature inspection), falling back to `broadcast_buffers` on older torch. Semantic nuance: with the new parameter, `False` still synchronizes buffers once at initialization — acceptable (arguably better) for the discriminator use case.
2. **Rank-0 checkpoint guard restructured for the type checker.** The plan's "wrap dir creation in `is_main_process()`" would leave `checkpoint_dir_` possibly unbound for `basedpyright`. Implemented instead as `checkpoint_dir_: pathlib.Path | None = None`, assigned only on the main process; all save sites guard on `checkpoint_dir_ is not None` (which is the rank-0 check and the type narrowing in one condition). Same behavior, lint-clean.
3. **Regression-test values are torch-version-pinned.** The frozen loss trajectories were generated with torch 2.13.0 on CPU and embedded as constants; the test file's `__main__` entry point regenerates them (`python tests/opt/test_train_single_process_regression.py`) after a torch version bump.
4. **`torch.multiprocessing.spawn` import.** `basedpyright` rejects `torch.multiprocessing.spawn` as not re-exported; tests import it from the defining submodule: `from torch.multiprocessing.spawn import spawn`.
5. **GPU-proofing the CPU test suite.** Spawned test workers set `CUDA_VISIBLE_DEVICES=""` before the first CUDA query (in `tests/opt/ddp_test_utils.py`), so `initialize()` selects gloo/CPU even on machines with GPUs and `make test` stays hardware-independent.
6. **Verification outcomes (2026-08-04).** All gates green: `make format-check`, `make lint` (0 errors), `make test` (99 passed; 83 pre-existing + 16 new, frozen trajectories unchanged after the refactor incl. the `no_grad` fix). Real-launcher smoke `torchrun --standalone --nproc-per-node=2` on CPU: both ranks report identical reduced `loss_mean` trajectories, no warnings. The gradient-penalty double-backward test through the wrapped discriminator (Section 4's risk gate) passes. Still pending from Section 12: manual GPU-node and multi-node runs, and the mops_gan migration (step 7).
