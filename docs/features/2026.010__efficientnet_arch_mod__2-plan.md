# Plan: Configurable Network Styles for `ScalableEfficientNet1D`

## Context

**Why.** With `enable_spectral_norm=True`, every convolution of an EfficientNet block feeds a `BatchNorm1d`, which cancels the spectral normalization (`2026.010__efficientnet_arch_mod__1-explore.md`, Section 1.1). The exploration lists ways to keep, replace, move, or remove these normalizations, to scale the residual sum, and to normalize depthwise convolutions exactly. All of them need capabilities that the network lacks today: choosing the normalization at each position, including none, a convolution bias, a pre-norm, a residual scale, and a depthwise spectral normalization, all set consistently for the whole network.

**Current state.**

- `MBConvConfig` (`dlk/nets/efficientnet1d.py`) is a `NamedTuple` with seven fields: `kernel_size`, `stride`, `expand_ratio`, `input_channels`, `output_channels`, `num_layers`, `se_ratio`. Both `MBConv1D` and `FusedMBConv1D` take it, and `StageSpec.config` holds it.
- `MBConv1D` hard-codes three `BatchNorm1d` layers, after the expansion, depthwise, and projection convolutions. `FusedMBConv1D` hard-codes two, after the fused and projection convolutions. The stem and head each hard-code one. Every convolution has `bias=False`.
- `ScalableEfficientNet1D.__init__` derives scaled and per-block configs with `cfg._replace(...)` (scaling) and `stage_config._replace(...)` (stride 1 and input channels for blocks after the first of a stage). `dlk/nets/cli_efficientnet.py` repeats the per-block rule by hand.
- `ScalableEfficientNet1D` and the 20 named variants take `stem_channels`, `head_channels`, `enable_stem`, `enable_head`, `dropout_head`, and `enable_spectral_norm` as separate arguments; every new setting would be repeated in all 20 variants.
- `UniversalMultiLevelBlock` (`dlk/nets/conv1d.py`) already takes a normalization as a `NormalizationFactory`, defined in `dlk/nets/utils.py` as `Callable[[int], nn.Module]`, and scales its residual sum with `skip_scale`.

**Gaps.**

- No block, stem, or head can drop or replace a normalization, and no convolution can get a bias.
- There is no pre-norm position at the block input or before the head.
- The residual sum cannot be scaled.
- Spectral normalization of a depthwise convolution uses the reshaped `(C, k)` kernel matrix, whose $\sigma$ overestimates the operator norm.
- A `NamedTuple` has no validation hook, and `num_layers`, a stage setting, sits in the block config.

**Settled design decisions.**

1. **Config versus style.** Two kinds of frozen dataclasses separate what differs per variant from what is consistent across the network. A **config** holds sizes and layout, set by the config builders and the named variants: `MBConvConfig`, `StageConfig`, `StemConfig`, `HeadConfig`. A **style** holds design choices that apply to every block of a network: normalizations, biases, residual scale, and spectral normalization: `MBConvStyle`, `FusedMBConvStyle`, `StemStyle`, `HeadStyle`, bundled in `NetStyle`. Frozen keeps the value semantics of today's `NamedTuple`: `ScalableEfficientNet1D` hands the same config object to the first block of a stage and keeps it in `self.stage_configs`, and a frozen dataclass raises on assignment instead of silently changing both. `dataclasses.replace` replaces `_replace`.
2. **Values are concrete.** Every field holds the value that is built; there is no `None`-means-auto placeholder and no resolution step. Sensible defaults come from the default values and from named presets. Hence `print(style)` shows the architecture, and `dataclasses.replace` can neither lose nor stale a derived value. Resolving placeholders in `__post_init__` has both failure modes: an `InitVar` input is reset to its default by `replace` (see the `AdamConfig` item in the Unrelated Observations section), and a field resolved once is not re-resolved when `replace` later changes the value it was derived from.
3. **Normalizations** are `NormalizationFactory | None`, as in `UniversalMultiLevelBlock`; `None` means no normalization at that position.
4. **One `ConvNorm` per convolution.** A frozen dataclass `ConvNorm(normalization: NormalizationFactory | None = nn.BatchNorm1d, bias: bool = False)` holds the two settings that belong to one convolution: its bias and the normalization after it. Two module-level presets name the common pairings: `BATCH_NORM = ConvNorm(nn.BatchNorm1d, bias=False)` (today) and `NO_NORM = ConvNorm(None, bias=True)` (the bias takes over the role of the normalization's $\beta$). Other pairings are written out, e.g., `ConvNorm(partial(nn.GroupNorm, 1), bias=True)`.
5. **Block styles.**
   - `MBConvStyle`: `pre_normalization: NormalizationFactory | None = None` (P0); `expand`, `depthwise`, `project: ConvNorm = BATCH_NORM` (P1, P2, P3); `skip_scale: float = 1.0`; `depthwise_spectral_norm: Literal["matrix", "exact"] = "matrix"` (C0 or C2, decision 11).
   - `FusedMBConvStyle`: `pre_normalization` (F0); `fused`, `project: ConvNorm = BATCH_NORM` (F1, F2); `skip_scale: float = 1.0`.
   - The pre-norm has no convolution before it inside the block, so it is a plain factory.
   - When a block has no convolution at a position, that field is ignored: `expand` in `MBConvStyle` and `project` in `FusedMBConvStyle` when `expand_ratio == 1`. This matches today, where these blocks have no normalization there either, and lets one style work for every stage.
6. **`skip_scale`** mirrors `skip_scale` of `UniversalMultiLevelBlock`: a block with a residual computes `skip_scale * (x + f(x))`. `1` gives today's residual sum, `0.5` the average (a convex combination, idea R4 of the explore doc with $\alpha = 1/2$), and `1 / sqrt(2)` preserves the variance of two independent branches (idea R3). The block's Lipschitz bound becomes `skip_scale * (1 + L_f)`. Blocks without a residual (stride 2 or a channel change) ignore it.
7. **Stem and head.** `StemConfig(channels: int)` and `HeadConfig(channels: int = 1280, dropout: float = 0.2)` hold the sizes; `StemStyle(conv: ConvNorm = BATCH_NORM)` and `HeadStyle(pre_normalization: NormalizationFactory | None = None, conv: ConvNorm = BATCH_NORM)` hold the design. The head's pre-norm normalizes the last block's output before the head convolution, the counterpart of a final normalization in pre-norm networks.
8. **`NetStyle`** bundles `mbconv: MBConvStyle`, `fused: FusedMBConvStyle`, `stem: StemStyle`, `head: HeadStyle`, `enable_spectral_norm: bool = False`, and `dropout_connect_mode: Literal["dropout", "drop_path"] = "dropout"` (decision 17), all defaulting to today's network. `NetStyle()` is the paper's EfficientNet.
9. **Network arguments.** `ScalableEfficientNet1D` takes `stem: StemConfig | None` (required, as `stem_channels` is today), `head: HeadConfig | None = HeadConfig()`, and `style: NetStyle = NetStyle()`; `None` disables the stem or head. These replace `stem_channels`, `head_channels`, `enable_stem`, `enable_head`, `dropout_head`, and `enable_spectral_norm`. The 20 named variants take `stem`, `head`, and `style` with their own defaults, e.g., `stem: StemConfig | None = StemConfig(channels=24)` and `head: HeadConfig | None = HeadConfig(dropout=0.3)`, so a new style setting adds no argument to the 20 variants.
10. **Blocks take their style separately from their config.** `MBConv1D(config, enable_spectral_norm=False, style=MBConvStyle())` and `FusedMBConv1D(config, enable_spectral_norm=False, style=FusedMBConvStyle())`; the positional `dropout` argument moves into the config (decision 17). `ScalableEfficientNet1D` passes `style.enable_spectral_norm` and the block style that `NetStyle.for_block(block_cls)` returns: `mbconv` for `MBConv1D` and its subclasses, `fused` for `FusedMBConv1D`; another block class raises `TypeError`. Consequences:

    - Both blocks keep sharing one `MBConvConfig`, since the configs differ in no field. The earlier idea of a `FusedMBConvConfig` subclass is dropped, and so is a function that sets normalizations per stage list.
    - A style is consistent across the network by construction. Different styles per stage need blocks built by hand; no current use needs that.
11. **C2: exact spectral normalization of depthwise convolutions.** A parametrization divides the whole depthwise weight by one scalar, the operator norm $\max_{c, \omega} \lvert \hat w_c(\omega) \rvert$, where $\hat w_c$ is the DFT of channel $c$'s filter, zero-padded to $n = 64$ points. This is the depthwise analogue of PyTorch's spectral normalization, which divides by $\sigma$: the layer gets operator norm 1, and the channels keep their relative gains. Stride only subsamples. $\lvert \hat w_c(\omega) \rvert$ is a trigonometric polynomial of degree $k - 1$, so sampling at $n$ points underestimates its maximum by at most the factor $1 - (k - 1)\pi/n$ (Bernstein's inequality), i.e., by at most 20% for $k = 5$ and $n = 64$; the docstring states this. The parametrization is applied only to the depthwise convolution of `MBConv1D`, only when `enable_spectral_norm` is set and `depthwise_spectral_norm == "exact"`; all other convolutions keep C0.
12. **Initialization of C2 layers.** A parametrized layer recomputes `weight` from `parametrizations.weight.original` on every access, so writing into `weight` has no effect. `_initialize_weights` catches PyTorch's spectral normalization in its first branch (plan 2026.009), but not the new parametrization, which would fall into the `nn.Conv1d` branch and stay uninitialized. A second branch catches C2 layers and writes Kaiming values (today's depthwise initialization) into `original`. Orthogonal initialization, used for C0 layers, does not fit: a `(C, k)` matrix with $C > k$ cannot have orthonormal rows.
13. **Stage logic in the dataclasses.** `StageSpec` is renamed `StageConfig`, consistent with the other configs, and becomes a frozen dataclass `StageConfig(block_cls, config, num_blocks)`. `num_blocks` is today's `num_layers`: a stage setting, it moves out of the block config and is renamed after what it counts. Three methods replace the two `_replace` calls in `ScalableEfficientNet1D` and the copy of the per-block rule in the CLI:

    - `MBConvConfig.scaled(width_coefficient, depth_divisor=8, min_depth=None) -> Self` applies `round_filters` to both channel counts; `StemConfig.scaled` and `HeadConfig.scaled` do the same for `channels`.
    - `StageConfig.scaled(width_coefficient, depth_coefficient, depth_divisor=8, min_depth=None) -> StageConfig` scales the config and applies `round_repeats` to `num_blocks`.
    - `StageConfig.block_configs() -> list[MBConvConfig]` returns the config of each block: the stage config for the first block, and `replace(config, input_channels=config.output_channels, stride=1)` for the others. The configs are frozen, so the later blocks share one object safely.

    `round_filters` and `round_repeats` stay public module functions, which the methods call.
14. **Named presets.** The module defines six `NetStyle` presets, the configurations of this plan, with `GN = partial(nn.GroupNorm, 1)` (one group, i.e., normalization over channels and length per sample):

    | Preset | Stem | Blocks (P0 / P1–P3, F0 / F1–F2) | Head (pre / conv) | `skip_scale` | SN | Depthwise SN |
    | --- | --- | --- | --- | --- | --- | --- |
    | `BASELINE` | `BATCH_NORM` | none / `BATCH_NORM` | none / `BATCH_NORM` | 1.0 | off | n/a |
    | `BASELINE_GN` | `ConvNorm(GN, bias=True)` | none / `ConvNorm(GN)` | none / `ConvNorm(GN)` | 1.0 | off | n/a |
    | `SN_PRE_GN` | `NO_NORM` | `GN` / `NO_NORM` | `GN` / `NO_NORM` | 0.5 | on | C0 |
    | `SN_FLOORED_PRE_GN` | `NO_NORM` | floored GN / `NO_NORM` | floored GN / `NO_NORM` | 0.5 | on | C0 |
    | `SN_EXACT_DW_PRE_GN` | `NO_NORM` | `GN` / `NO_NORM` | `GN` / `NO_NORM` | 0.5 | on | C2 |
    | `SN_EXACT_DW_FLOORED_PRE_GN` | `NO_NORM` | floored GN / `NO_NORM` | floored GN / `NO_NORM` | 0.5 | on | C2 |

    - `BASELINE` equals `NetStyle()`, the paper's network.
    - `BASELINE_GN` keeps the baseline's positions and swaps the normalization layer, which makes the network batch independent for per-sample penalties. The stem bias keeps the input amplitude visible (explore doc, Section 1.3).
    - The four `SN_*` presets normalize only the input of each block and of the head, so spectral normalization binds in every branch convolution. They differ in two independent settings: the floored normalization, and C2 in place of C0 for the depthwise convolutions. The pairs with and without C2 isolate the effect of the exact depthwise normalization.
    - The floored normalization is N5 of the explore doc, which is `nn.GroupNorm` with `eps` $= \tau^2$: GroupNorm divides by $\sqrt{\mathrm{var} + \epsilon}$, and N5 by $\sqrt{s^2 + \tau^2}$. Its Lipschitz constant is at most $\max\lvert\gamma\rvert / \tau$; $\gamma$ stays learnable and unbounded, and bounding the normalization's gradient is the job of the penalties of plan 2026.008.
    - A function `sn_pre_gn_style(eps: float = 1e-5, depthwise_spectral_norm: Literal["matrix", "exact"] = "matrix") -> NetStyle` builds the four `SN_*` presets: `eps=1e-5` (GroupNorm's default) without flooring, and `eps=1.0`, i.e., $\tau = 1$, with flooring, a starting value for the examples of Section 4 to revisit.
    - The SE gate stays as it is in all presets; changes to it are deferred. It has no global Lipschitz bound, so the bounds above hold for SE-free blocks only.
15. **New module `dlk/nets/spectral_norm.py`** for spectral normalization: the existing `get_spectral_norm` and `set_spectral_norm` move there from `dlk/nets/utils.py`, next to the new C2 code (`DepthwiseSpectralNorm`, `set_depthwise_spectral_norm`, `get_depthwise_spectral_norm`). `set_init_parameters` stays in `utils.py`, because it initializes any weighted layer; it imports `get_spectral_norm` from the new module, which itself imports nothing from `utils.py`, so there is no import cycle. Every importer of the moved functions changes its import (Section 2). `utils.py` keeps no re-export: code outside the repo that imports the two functions from `dlk.nets.utils` breaks, which is accepted.
16. **Stage list naming.** The `stage_specs` argument of `ScalableEfficientNet1D` and the attributes `stage_specs` and `base_stage_specs` are renamed `stage_configs` and `base_stage_configs`, consistent with `StageConfig`.
17. **Dropout and drop path in the block config.** The residual-branch regularization of one block is a setting of that block, so `MBConvConfig` gets two rates:
    - `dropout: float = 0.0`: element-wise `nn.Dropout` on the branch output before the residual sum, as today's block argument `dropout`.
    - `drop_path: float = 0.0`: drop path, i.e., stochastic depth per sample, mirroring `drop_path` of `UniversalMultiLevelBlock` (`dlk/nets/conv1d.py`): in training mode, the whole branch of a sample is dropped with probability `drop_path`, and the kept branches are scaled by `1 / (1 - drop_path)`. The block then computes `skip_scale * (mask * f(x) / (1 - drop_path) + x)`.
    - `__post_init__` asserts both rates in `[0, 1)` and at most one of them positive, so drop path is an alternative to dropout. A property `has_residual` (`stride == 1` and `input_channels == output_channels`) replaces the blocks' own `use_residual` computation; as in `UniversalMultiLevelBlock`, which raises when drop path has no skip branch, `__post_init__` asserts `drop_path == 0` for a config without residual. Dropout keeps today's behavior and is ignored without residual.

    The network-wide maximum rate stays the argument `dropout_connect` of `ScalableEfficientNet1D` and the named variants: it is a regularization strength, like the head dropout in `HeadConfig`, and the linear ramp over all blocks needs the block's index across stages, which only the network knows. The block loop sets the ramped rate `dropout_connect * block_index / total_blocks` with `replace(block_config, dropout=rate)`, or with `replace(block_config, drop_path=rate)` for blocks with residual when `style.dropout_connect_mode == "drop_path"`. The mode is a style: it chooses the kind of operation consistently for all blocks, while its strength is a config value. The comment `# Stochastic depth (drop connect)` at the ramp is corrected: the default mode is element-wise dropout, and `"drop_path"` is stochastic depth. A critic sets `dropout_connect=0` and `HeadConfig(dropout=0)`, since either kind of dropout makes the critic random within one penalty evaluation; the usage doc says so.

**Core principle.** The default style builds today's network: the same modules, parameter names, initialization, and forward output. Every change of behavior comes from a non-default style. The default `skip_scale = 1.0` multiplies exactly in floating point, so the forward output stays bit-identical.

Consequences, i.e., what needs no change:

- `SqueezeExcitation1DLinear`, which keeps its `enable_spectral_norm` argument.
- `_initialize_weights` apart from the C2 branch (decision 12): its `nn.Conv1d` and C0 branches already zero any bias, and `GroupNorm` initializes its affine parameters with ones and zeros, as the `BatchNorm1d` branch does.
- `round_filters` and `round_repeats`.
- The config builders apart from the move of `num_layers` and the class rename.

Four changes are not opt-in, because they change names and constructor signatures: `get_spectral_norm` and `set_spectral_norm` move to `dlk/nets/spectral_norm.py` (decision 15); `StageSpec` becomes `StageConfig` with `num_blocks` in place of the block config's `num_layers`, and `stage_specs` becomes `stage_configs` (decisions 13 and 16); `stem`, `head`, and `style` in place of six arguments of `ScalableEfficientNet1D` and the named variants (decision 9); and the blocks' `dropout` argument replaced by the config fields `dropout` and `drop_path`, with `style` as a new keyword (decisions 10 and 17). Every place that names `StageSpec`, builds stage configs, or builds networks with the replaced arguments changes (Sections 1.4, 2, and 3). The networks they build with default values stay the same.

## Terminology

- **`NormalizationFactory`**: a callable that takes a channel count and returns a normalization module, e.g., `nn.BatchNorm1d` or `partial(nn.GroupNorm, 1)`.
- **Config**: a frozen dataclass with sizes and layout that differ per variant or stage (`MBConvConfig`, `StageConfig`, `StemConfig`, `HeadConfig`). **Style**: a frozen dataclass with design choices that are the same for every block of a network (`MBConvStyle`, `FusedMBConvStyle`, `StemStyle`, `HeadStyle`, `NetStyle`).
- **Positions in `MBConv1D`**: **P0** at the block input, before the expansion (pre-norm, field `pre_normalization`); **P1** after the expansion convolution (`expand`); **P2** after the depthwise convolution (`depthwise`); **P3** after the projection convolution (`project`).
- **Positions in `FusedMBConv1D`**: **F0** at the block input (`pre_normalization`); **F1** after the fused convolution (`fused`); **F2** after the projection convolution (`project`).
- **`ConvNorm`**: the bias of one convolution and the normalization after it. **`BATCH_NORM`**, **`NO_NORM`**: module-level `ConvNorm` presets.
- **Preset**: a module-level `NetStyle` constant that names one configuration (decision 14).
- **Pre-norm**: the normalization is applied to the block input $x$ inside the residual branch, so the block computes `skip_scale * (x + f(N(x)))`; the identity path stays unnormalized.
- **C0, C2**: spectral normalization of a convolution through its reshaped kernel matrix (PyTorch's `spectral_norm`), and through the exact operator norm of a depthwise convolution (decision 11).
- **Floored normalization**: GroupNorm with a large `eps` $= \tau^2$, whose gain is bounded by $\max\lvert\gamma\rvert / \tau$.
- **Frozen dataclass**: `@dataclass(frozen=True)`; assigning a field raises `FrozenInstanceError`, and `dataclasses.replace(obj, field=value)` returns a modified copy.

### 1.5 Module layout

With the default style, the `nn.Sequential` containers keep their current order and indices (conv at 0, normalization at 1, SiLU at 2), so `state_dict` keys are unchanged. With `NO_NORM`, the normalization is left out of its `nn.Sequential`, so the SiLU moves to index 1 and the convolution gains a `.bias` key. The block and head pre-norms are `nn.Identity()` by default and add no parameters or keys.

## 4. Examples

Two scripts in `examples/nets/`, in the style of `compose_replica_latents.py` (module docstring with the run command), on CPU with `EfficientNetV1BB0` and `EfficientNetV2BB0`, plotted with matplotlib. Both compare the six presets.

- **`efficientnet_signal_propagation.py`**: signal propagation plots (explore doc, Section 6, item 2; [Brock et al., 2021a]) at initialization: per block, the mean squared activation and the channel-mean squared of the residual stream on random inputs. It shows how `skip_scale = 0.5` and the pre-norm shape the stream across a stage.
- **`efficientnet_empirical_lipschitz.py`**: manufactured data from sums of radial basis functions in time, e.g., $x(t) = \sum_j a_j \exp(-(t - t_j)^2 / (2 w_j^2))$ with random amplitudes, centers, and widths. For the whole network and for each block, it estimates the Lipschitz constant from below by the largest input-gradient norm and by the largest finite-difference quotient over random pairs and interpolations. It compares the estimates per block with the rough bound of the explore discussion, $\text{skip\_scale} \cdot (1 + L_\text{branch} \cdot \max\lvert\gamma\rvert / \tau)$, with the SE layers turned on and off (`se_ratio=None` in the stage configs).
- **Running them.** Both scripts take an output directory for their figures (default: the current directory), use the non-interactive `Agg` backend, and finish in about a minute on CPU. `tests/nets/test_examples_compose.py` runs the examples as subprocesses; a sibling test file `tests/nets/test_examples_efficientnet.py` runs the two new scripts the same way, with a `tmp_path` output directory.

## 5. Application migration sketch

A critic that uses the new styles:

```diff
from dlk.nets.efficientnet1d import EfficientNetV2BB0, HeadConfig, SN_EXACT_DW_FLOORED_PRE_GN

EfficientNetV2BB0(
    input_channels=input_channels,
    input_length=input_size,
    num_classes=output_size,
    dropout_connect=dropout,
-   dropout_head=dropout,
+   head=HeadConfig(dropout=dropout),
+   style=SN_EXACT_DW_FLOORED_PRE_GN,
)
```

Other changes an application may meet:

- `enable_spectral_norm=True` on a network becomes a style, e.g., `style=replace(BASELINE, enable_spectral_norm=True)` for today's behavior.
- `enable_stem=False` and `enable_head=False` become `stem=None` and `head=None`; `stem_channels` and `head_channels` become `StemConfig(channels=...)` and `HeadConfig(channels=...)`.
- Custom stage lists build `StageConfig(block_cls, MBConvConfig(...), num_blocks=...)` and pass them as `stage_configs=`.
- `from dlk.nets.utils import set_spectral_norm` (or `get_spectral_norm`) becomes `from dlk.nets.spectral_norm import ...`.
- Checkpoints of networks built with a non-default style do not load into a network built with another style (Section 11).

## 8. Unrelated Observations and Improvements (report only)

- **`AdamConfig`, `AdamWConfig`, `SGDConfig`** (`dlk/opt/optimizer.py`) resolve `fused` and `foreach` in `__post_init__` from the constructor-only `InitVar`s `param_fused` and `param_foreach`. Checked with `torch.accelerator.is_available` patched to `True`:
	
    - `dataclasses.replace(cfg, lr=1e-4)` silently drops explicit settings. `replace` passes only `init` fields, so the `InitVar`s fall back to `None` and the heuristic runs again: a config built with `param_fused=False` comes back with `fused=True`.
    - `dataclasses.replace(cfg, fused=False)` raises `ValueError`, because `fused` is `init=False`. The resolved field cannot be set through `replace`.
    - The dataclasses are not frozen, so `cfg.fused = True; cfg.foreach = True` bypasses the mutual-exclusion check in `_resolve_fused_foreach`; the error appears only when `torch.optim` builds the optimizer.
    - The name of a setting differs between input (`param_fused`) and output (`fused`). `from_dict` maps the names, but direct construction with `fused=...` raises `TypeError`.
    - Possible fix in line with decision 2 of this plan: store the user's setting as a plain field (`fused: bool | None = None`), keep it frozen, and resolve the heuristic where the optimizer is built (`to_kwargs`), which is also when the model is on its device.

- **`dlk/nets/mlp.py`** calls `spectral_norm` directly in eight places; `set_spectral_norm` from the new module would make those wraps idempotent (also noted in plan 2026.009, Section 7).

## 11. Risks and Edge Cases

- **API break.** Four changes break callers (Core principle): the module move, the `StageConfig` and `stage_configs` renames, the six replaced network arguments, and the blocks' new signature. Accepted; Section 5 lists the migration, and the only known external caller is `fhn_gan`.
- **Checkpoints.** A non-default style changes the parameter set: pre-norm weights, convolution biases, removed normalizations, and the C2 parametrization keys (`parametrizations.weight.original` plus no power-iteration buffers). Checkpoints load only into a network with the same style; the default style keeps today's keys.
- **C2 underestimates the norm** by at most the factor $1 - (k - 1)\pi/64$ (20% for $k = 5$), so a C2 layer can have operator norm up to $1/0.8$. Acceptable for soft control; a larger `dft_length` shrinks it.
- **C2 cost and compilation.** One `rfft` of a `(C, 64)` tensor per forward, also in eval mode, since the parametrization has no cached estimate. Behavior under `torch.compile` is unverified (Section 10).
- **`skip_scale = 0.5`.** The residual stream becomes an average: a block's input reaches the output $j$ blocks later with weight $0.5^j$, and so does the gradient through the skip path. Long stages (15 blocks in V2-S, 32 in V2-XL) may train poorly; the signal propagation example measures this.
- **GroupNorm with one group** normalizes each sample over all channels and positions, which also removes the overall scale of the stream at each pre-norm. The stem and convolution biases keep the input amplitude visible; the amplitude test of Section 6c guards this.
- **The SE gate and $\gamma$ are unbounded.** All presets keep the SE gate, and the normalizations' $\gamma$ is learnable. The styles bound the convolutions, not the network; the penalties of plan 2026.008 do the rest.
- **Dropout in a critic.** Element-wise dropout and drop path both make the critic random in training mode, so the two critic evaluations of a gradient or finite-difference penalty see different networks. Critics run with `dropout_connect=0` and `HeadConfig(dropout=0)`; the presets do not set these, because they are configs, and the usage doc states it.
- **Dataclass equality.** `functools.partial` objects compare by identity, so two styles built by separate calls of `sn_pre_gn_style` are not equal, although they build the same network. Tests compare built modules, not styles.
- **Custom block classes.** `NetStyle.for_block` raises `TypeError` for a block class that is neither `MBConv1D` nor `FusedMBConv1D` nor a subclass of one. No such class exists in the toolkit or its examples.
