# Usage: Distributed Training with `dlk.opt.distributed`

Companion to the plan in [[2026.02__ddp__1-plan]] (see its Nomenclature section for jargon). DDP support is opt-in: without a launcher, every helper degrades to a no-op/passthrough and applications run single-process exactly as before.

## API overview

```python
from dlk.opt import distributed

ctx = distributed.init_distributed()      # DistributedContext: rank, local_rank,
                                          #   world_size, device, is_main, is_distributed
net = distributed.wrap_ddp(net, ctx.device)
sampler = distributed.create_distributed_sampler(dataset, shuffle=True, seed=base_seed)
distributed.seed_random_generators(base_seed)   # seeds with base_seed + rank
distributed.finalize_distributed()

# rank helpers (all safe single-process):
distributed.is_distributed(); distributed.get_rank(); distributed.get_world_size()
distributed.is_main_process(); distributed.barrier()
distributed.unwrap_ddp(net)               # net.module if wrapped

# checkpoint I/O (dlk.opt.utils):
from dlk.opt.utils import checkpoint_load, checkpoint_save
epoch = checkpoint_load(path, net, optimizer=opt, map_location=ctx.device)
```

The train loops (`dlk.opt.train`, `dlk.opt.train_gan`, `dlk.opt.train_diffusion`) are rank-aware
internally — no new arguments:

- checkpointing and validation run on the main process only; `validation_fn` receives the unwrapped model(s);
- the distributed sampler's epoch is advanced automatically each epoch;
- loss statistics in the returned `TrainLog` are reduced exactly across all processes;
- tqdm progress bars and profiler table printing appear on the main process only.

## Migration recipe (application side)

The changes to an application like `mops_gan` are:

```python
from dlk.opt import distributed as dlk_dist

# 1. replace device selection
dist_ctx = dlk_dist.init_distributed()
device = dist_ctx.device

# 2. rank-suffix log files (dlk.mgmt.log opens files with mode="w")
log_name = name if not dist_ctx.is_distributed else f"{name}_rank{dist_ctx.rank}"
logging_set_up(save_dir / log_name)

# 3. replace manual seeding (rank-offset; keep the base seed for the sampler)
dlk_dist.seed_random_generators(base_seed)

# 4. wrap models after moving them to the device
net = dlk_dist.wrap_ddp(net, device)
g_net = dlk_dist.wrap_ddp(g_net, device)
d_net = dlk_dist.wrap_ddp(d_net, device, broadcast_buffers=False)

# 5. thread the sampler into DataLoader creation
sampler = dlk_dist.create_distributed_sampler(dataset, shuffle=shuffle, seed=base_seed)
if sampler is not None:
    dataloader_kwargs["sampler"] = sampler
    dataloader_kwargs["shuffle"] = False    # mutually exclusive with sampler

# 6. after training: only the main process continues to predict/eval/plot
dlk_dist.finalize_distributed()
if not dist_ctx.is_main:
    return
```

Caveats for the application:

- `multiprocessing_context="fork"` in DataLoader kwargs is unsafe once CUDA is initialized; use `"spawn"` or `num_workers=0` under DDP. `num_workers` is *per rank*.
- Weight loading with `torch.load(..., map_location=device)` works unchanged; prefer the new `checkpoint_load` for checkpoints written by the train loops.
- GAN specifics: wrap generator and discriminator independently; keep `find_unused_parameters=False` and `static_graph=False`.

## Launching

Single node, 4 GPUs (or 4 CPU processes when no GPU is present):

```sh
torchrun --standalone --nproc-per-node=4 run.py -p configs/post_est_gan.yaml
```

Single-node Slurm job:

```sh
#SBATCH --nodes=1
#SBATCH --ntasks-per-node=1
#SBATCH --gpus-per-node=4

srun torchrun --standalone --nproc-per-node=$SLURM_GPUS_PER_NODE run.py
```

Multi-node Slurm job (c10d rendezvous on the head node):

```sh
#SBATCH --nodes=2
#SBATCH --ntasks-per-node=1
#SBATCH --gpus-per-node=4

head_node=$(scontrol show hostnames "$SLURM_JOB_NODELIST" | head -n 1)
srun torchrun \
    --nnodes=$SLURM_JOB_NUM_NODES \
    --nproc-per-node=$SLURM_GPUS_PER_NODE \
    --rdzv-backend=c10d \
    --rdzv-endpoint=$head_node:29500 \
    run.py
```

Slurm fallback without torchrun (one Slurm task per process; requires exporting the rendezvous address, this is the contract of the fallback):

```sh
#SBATCH --nodes=2
#SBATCH --ntasks-per-node=4
#SBATCH --gpus-per-node=4

export MASTER_ADDR=$(scontrol show hostnames "$SLURM_JOB_NODELIST" | head -n 1)
export MASTER_PORT=29500
srun python run.py
```

CPU-only clusters work with the same commands; the backend auto-selects gloo when CUDA is unavailable (`init_distributed(backend="gloo")` forces it).

Debugging tips: `export NCCL_DEBUG=INFO` for verbose NCCL logging; `NCCL_SOCKET_IFNAME=<iface>` to pin the network interface.

## Profiling under DDP

`dlk.opt.profiler` works per rank: call `profile_train_epochs`/`profile_train_batches` on every rank with the DDP-wrapped model. Each rank writes rank-suffixed files (`table_prof_step_{N}_rank{r}.txt`, `trace_prof_step_{N}_rank{r}.json`); the summary table prints on the main process only. Single-process filenames are unchanged.

- Open a per-rank trace in Perfetto/chrome://tracing to see NCCL kernels (`ncclDevKernel_AllReduce...`) or gloo CPU collectives, and check that gradient all-reduce overlaps the backward pass. Comparing traces across ranks reveals stragglers.
- `record_shapes=True` (default in this module) annotates all-reduce bucket sizes, which is what to inspect when tuning DDP's `bucket_cap_mb`.
- `profile_train_batches` profiles 10 batches; for meaningful (unpadded) profiled batches the dataset should hold at least `10 * batch_size * world_size` samples.

## Testing

`tests/opt/` runs 2-process gloo groups via `torch.multiprocessing.spawn` inside plain
`make test` (no GPUs, no torchrun needed). A real-launcher CPU smoke test:

```sh
torchrun --standalone --nproc-per-node=2 <tiny-training-script>
```

On a GPU node verify: one process per GPU in `nvidia-smi` (pinned by `local_rank`), a single timestamped checkpoint directory, and resume via `checkpoint_load(..., map_location=ctx.device)`.
