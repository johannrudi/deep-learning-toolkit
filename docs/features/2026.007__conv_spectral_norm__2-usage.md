# Spectral Normalization for `ConvResNet` and the Universal Multi-Level Block

**Spectral normalization** ([Miyato et al., 2018]) rescales a layer's weight by its largest singular value on every forward pass, so the layer never stretches its input by more than a factor of 1. `MLPResNet` has offered this as `enable_spectral_norm` for its linear layers; `dlk/nets/conv1d.py` now offers the same flag for every convolution built by `ConvResNet`, `UniversalMultiLevelBlock`, and the blocks derived from it (`DownsampleBlock`, `UpsampleBlock`, `LevelBlock`, `ConvNeXtBlock`). This helps constrain a `ConvResNet` critic in a WGAN, where the discriminator needs a Lipschitz bound; the flag alone does not give that bound (see Getting a strict Lipschitz bound).

The flag is off by default and changes nothing when off: no module, parameter name, initialization, or forward output differs from a network built without it. Turning it on renames the wrapped layers' parameters in the `state_dict`, which is why a checkpoint from one setting will not load into the other (see Things worth knowing).

## Enabling the flag

### Step 1: Turn it on for a `ConvResNet`

Add `enable_spectral_norm` to `conv_resnet_params`, next to `use_dropout`. It wraps `input_layer` and every convolution of every `LevelBlock`, including the skip convolutions:

```python
net = ConvResNet(
    input_channels=1,
    input_length=64,
    conv_resnet_params={
        "channels_mult": [4, 8, 16],
        "kernels": [3, 3, 3],
        "enable_spectral_norm": True,
    },
    mlp_resnet_params={
        "output_size": 1,
        "residual_blocks_sizes": [(16 * 8, 32, 64, 16)],
        "enable_spectral_norm": True,
    },
)
```

`ConvResNet` never sets `mlp_resnet_params["enable_spectral_norm"]` for you. An MLP head needs its own flag, or it stays unconstrained while the convolutional trunk is bounded.

### Step 2: Turn it on for a bare block

`UniversalMultiLevelBlock` and its subclasses (`DownsampleBlock`, `UpsampleBlock`, `LevelBlock`, `ConvNeXtBlock`) take the same flag directly:

```python
block = ConvNeXtBlock(input_channels=8, kernel_size=7, enable_spectral_norm=True)
```

`ConvNeXtBlock`'s depthwise convolution is grouped, one group per channel. PyTorch's `spectral_norm` reshapes the whole weight into one matrix and normalizes it jointly, which bounds every group (every channel) by 1 but can shrink a group harder than that group alone would need. There is no per-group spectral norm in PyTorch to opt out of this with.

### Step 3: Confirm the wrapping, if you are unsure

`parametrize.is_parametrized(layer, "weight")` from `torch.nn.utils` is `True` for every convolution the flag reaches:

```python
from torch.nn.utils import parametrize

assert parametrize.is_parametrized(net.input_layer, "weight")
```

`tests/nets/test_conv1d.py::test_convresnet_spectral_norm_wraps_every_conv` is the ship-gate version of this check: it counts the input layer, three convolutions per level, and one skip convolution per level that changes channels, and asserts every one of them is wrapped while the MLP head's linears are not.

## Getting a strict Lipschitz bound

The flag alone does not make a `ConvResNet` 1-Lipschitz. `UniversalMultiLevelBlock`'s defaults, `GroupNorm` normalization and `GELU` activation, have no Lipschitz bound (`GroupNorm` divides by a per-sample standard deviation) or a bound above 1 (`GELU` is about 1.13-Lipschitz). Getting an actual bound needs four more settings, on top of the flag:

```python
block_kwargs = {
    "normalization": False,
    "activation": nn.ReLU(),
    "skip_scale": 0.5,
    "conv_kwargs": {"padding_mode": "zeros"},
}
```

With these, and a skip connection, a block satisfies $L_\text{block} \le 0.5 \, (1 + \sqrt{k})$ for kernel size $k$. The $\sqrt{k}$ factor, not 1, is the part worth remembering: PyTorch's `spectral_norm` bounds the *reshaped kernel matrix* of shape `(out_channels, in_channels / groups * kernel_size)`, and for `kernel_size > 1` the convolution's true operator norm can exceed that matrix's spectral norm by up to $\sqrt{k}$ ([Sedghi et al., 2019]). Only the 1x1 convolutions, including the skip convolution, get the exact bound of 1. Section 1.1 of the plan ([[2026.007__conv_spectral_norm__1-plan]]) has the full derivation, including what stride, replicate padding, and `skip_scale` each contribute.

`tests/nets/test_conv1d.py::test_multilevel_block_spectral_norm_lipschitz_bound` verifies this bound directly: it estimates each convolution's true operator norm with 50 steps of power iteration through `torch.func.vjp`, and checks the ratio $\|f(x) - f(y)\| / \|x - y\|$ over random input pairs against $0.5 \, (1 + \sqrt{k})$.

## Verifying a training run stays normalized

Optional; read this when wiring the flag into a WGAN critic. Spectral normalization estimates $\sigma$ with one power-iteration step per training-mode forward pass, so right after construction it is exact only because `set_init_parameters` (`dlk/nets/utils.py`) gives the wrapped layer an orthogonal weight and re-syncs the iteration vectors $u, v$. From then on $\sigma$ tracks the weight as it changes under the optimizer, one step behind.

A minimal manual check, without `dlk.opt`'s GAN training loop:

```python
import torch
from dlk.nets.conv1d import ConvResNet

critic = ConvResNet(
    input_channels=1,
    input_length=64,
    conv_resnet_params={"channels_mult": [4, 8, 16], "kernels": [3, 3, 3], "enable_spectral_norm": True},
    mlp_resnet_params={"output_size": 1, "residual_blocks_sizes": [(16 * 8, 32, 64, 16)], "enable_spectral_norm": True},
)
optimizer = torch.optim.Adam(critic.parameters(), lr=1e-3)

critic.train()
for _ in range(50):
    x_real = torch.randn(8, 1, 64)
    x_fake = torch.randn(8, 1, 64)
    optimizer.zero_grad()
    loss = critic(x_fake).mean() - critic(x_real).mean()
    loss.backward()
    optimizer.step()
```

After 50 Adam steps at `lr=1e-3`, the reshaped-matrix $\sigma$ of every wrapped weight stays within about 1.5% of 1 (`torch.linalg.matrix_norm(weight.flatten(1), ord=2)`), against the `rtol=1e-3` the ship-gate test gets when the weight stops changing between forwards. A training loop that raises no warnings and keeps $\sigma$ near 1 is behaving as designed; a $\sigma$ that drifts far from 1 across many steps usually means the learning rate is outrunning one power-iteration step per batch.

## Things worth knowing

**Checkpoints do not cross the flag.** With the flag on, a wrapped convolution's parameter is renamed from `weight` to `parametrizations.weight.original`, plus two buffers `parametrizations.weight.0._u` and `parametrizations.weight.0._v`. Decide on the flag before training runs you intend to resume from checkpoints; see Fixing common issues below for what a mismatch looks like.

**A `conv` factory that already wraps is left alone.** `ConvResNet` and `UniversalMultiLevelBlock` accept a `conv` factory for the layers they build. If that factory already returns a `spectral_norm`-wrapped layer, setting `enable_spectral_norm=True` on top does not wrap it twice; the internal `_spectral_norm` helper first checks for an existing spectral-norm parametrization with `get_spectral_norm` (`dlk/nets/utils.py`). This makes the flag safe to set unconditionally in application code that also passes a custom `conv`.

**Grouped and depthwise convolutions are wrapped, not treated specially.** `ConvResNet`'s `input_layer` (grouped by `input_channels`) and `ConvNeXtBlock`'s depthwise `conv_0` get the same joint reshaping as an ungrouped convolution; see Step 2.

**`torch.compile` is unverified.** A parametrization recomputes the weight on every forward, and this plan did not verify compile compatibility; treat it as untested until measured.

**Changing your mind.** Set `enable_spectral_norm=False` (the default) and rebuild the network; there is nothing else to undo. The old checkpoint loads again.

## Fixing common issues

**`TypeError: ... got multiple values for keyword argument 'enable_spectral_norm'`.** `enable_spectral_norm` was passed both in `conv_resnet_params` and inside `conv_resnet_params["block_kwargs"]`. Set it once, in `conv_resnet_params`; `dropout` fails the same way for the equivalent mistake.

**`RuntimeError: Error(s) in loading state_dict for ConvResNet: Missing key(s) in state_dict: "input_layer.parametrizations.weight.original", ...`.** A checkpoint saved with the flag off is being loaded into a network built with the flag on, or the reverse. Rebuild the network with the same `enable_spectral_norm` setting the checkpoint was trained under.
