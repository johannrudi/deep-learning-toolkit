# Spectral Normalization for 1D EfficientNets

> **The API changed in plan 2026.010.** `enable_spectral_norm` is now a field of the network's `style` (`NetStyle`), `StageSpec` became `StageConfig`, and new presets replace `BatchNorm1d` so that spectral normalization binds. The prose describes the network as of plan 2026.009, when `BatchNorm1d` was hard-coded. The examples below use the current API, which `docs/features/2026.010__efficientnet_arch_mod__3-usage.md` describes.

**Spectral normalization** ([Miyato et al., 2018]) rescales a layer's weight by its largest singular value on every forward pass, so the layer never stretches its input by more than a factor of 1. `MLPResNet` and `ConvResNet` offer this as `enable_spectral_norm` (see `docs/features/2026.007__conv_spectral_norm__2-usage.md`); `dlk/nets/efficientnet1d.py` now offers the same flag for `ScalableEfficientNet1D`, its 20 named variants (`EfficientNetV1BB0` to `EfficientNetV2XL`), and the blocks `MBConv1D`, `FusedMBConv1D`, and `SqueezeExcitation1DLinear`.

The flag is off by default and changes nothing when off: no module, parameter name, initialization, or forward output differs from a network built without it. `tests/nets/test_net_baselines.py` guards this.

Read the section What the flag bounds before relying on the flag for a Lipschitz constraint. Every EfficientNet block uses `BatchNorm1d`, so the flag does not make the convolutional body Lipschitz-bounded.

## Enabling the flag

### Step 1: Turn it on for a named variant

Every named variant takes the flag as a field of its `style`:

```python
from dataclasses import replace

from dlk.nets.efficientnet1d import NET_BASELINE, EfficientNetV2BB0

net = EfficientNetV2BB0(
    input_channels=1,
    input_length=64,
    num_classes=3,
    style=replace(NET_BASELINE, enable_spectral_norm=True),
)
```

### Step 2: Turn it on for `ScalableEfficientNet1D`

`ScalableEfficientNet1D` takes the same `style`. It passes the flag to every block with `stage.block_cls(config, style=..., enable_spectral_norm=...)`:

```python
from dataclasses import replace

from dlk.nets.efficientnet1d import (
    NET_BASELINE,
    FusedMBConv1D,
    HeadConfig,
    MBConv1D,
    MBConvConfig,
    ScalableEfficientNet1D,
    StageConfig,
    StemConfig,
)

stage_configs = [
    StageConfig(
        FusedMBConv1D,
        MBConvConfig(
            kernel_size=3, stride=1, expand_ratio=1,
            input_channels=16, output_channels=16, se_ratio=None,
        ),
        num_blocks=1,
    ),
    StageConfig(
        MBConv1D,
        MBConvConfig(
            kernel_size=5, stride=2, expand_ratio=4,
            input_channels=16, output_channels=24, se_ratio=0.25,
        ),
        num_blocks=2,
    ),
]
net = ScalableEfficientNet1D(
    stage_configs=stage_configs,
    stem=StemConfig(channels=16),
    head=HeadConfig(channels=64),
    input_channels=1,
    input_length=64,
    num_classes=3,
    style=replace(NET_BASELINE, enable_spectral_norm=True),
)
```

A custom `block_cls` must subclass `MBConv1D` or `FusedMBConv1D` and accept the keywords `style` and `enable_spectral_norm`, even with the flag off (see Fixing common issues).

### Step 3: Turn it on for a single block

`MBConv1D`, `FusedMBConv1D`, and `SqueezeExcitation1DLinear` take the flag directly:

```python
from dataclasses import replace

from dlk.nets.efficientnet1d import (
    FusedMBConv1D,
    MBConv1D,
    MBConvConfig,
    SqueezeExcitation1DLinear,
)

config = MBConvConfig(
    kernel_size=3, stride=1, expand_ratio=4,
    input_channels=8, output_channels=8, se_ratio=0.25,
)
mbconv = MBConv1D(config, enable_spectral_norm=True)
fused = FusedMBConv1D(replace(config, se_ratio=None), enable_spectral_norm=True)
se = SqueezeExcitation1DLinear(channels=32, squeeze_channels=2, enable_spectral_norm=True)
```

`FusedMBConv1D` requires `se_ratio=None`, hence the `replace`. A standalone block keeps PyTorch's default initialization. `spectral_norm` runs 15 power-iteration steps when it registers, so $\sigma$ is accurate from the start.

### Step 4: Confirm the wrapping, if you are unsure

`parametrize.is_parametrized(layer, "weight")` from `torch.nn.utils` is `True` for every layer the flag reaches. This lists any `Conv1d` or `Linear` layer that is not wrapped, and it is empty for a network built with the flag on:

```python
import torch.nn as nn
from torch.nn.utils import parametrize

unwrapped = [
    name
    for name, module in net.named_modules()
    if isinstance(module, (nn.Conv1d, nn.Linear))
    and not parametrize.is_parametrized(module, "weight")
]
assert not unwrapped
```

`tests/nets/test_efficientnet1d.py::test_efficientnet_spectral_norm_wraps_every_conv_and_linear` is the ship-gate version of this check for `EfficientNetV2BB0`.

## Which layers are wrapped

The flag wraps every `nn.Conv1d` and `nn.Linear` of the network:

- the stem convolution (unless `stem=None`);
- in `MBConv1D`, the expansion convolution (when `expand_ratio != 1`), the depthwise convolution, and the projection convolution;
- in `FusedMBConv1D`, the fused convolution and the projection convolution (when `expand_ratio != 1`);
- in every block with squeeze-and-excitation (SE), the `reduce` and `expand` layers of `SqueezeExcitation1DLinear`;
- the head's 1x1 convolution and the classifier `nn.Linear` (unless `head=None`).

There is one flag for the whole network. It cannot exclude a single layer type.

`SqueezeExcitation1DConv` has no flag. No block, network, test, or example uses it.

`BatchNorm1d`, `SiLU`, `Sigmoid`, `Dropout`, and pooling layers are not weighted layers in this sense and are left as they are.

## Initialization

`ScalableEfficientNet1D` initializes each wrapped layer with `set_init_parameters` (`dlk/nets/utils.py`) and then sets its bias to zero. `set_init_parameters` gives the trainable weight an orthogonal initialization and re-syncs the power-iteration vectors, so every wrapped layer starts with $\sigma = 1$ and all singular values of its reshaped kernel matrix equal to 1. Unwrapped layers keep EfficientNet's usual initialization, so a network built with the flag off is unchanged. A block built on its own does not go through this step (Step 3).

## What the flag bounds

Two parts of the network have no bound, and the first one matters most.

**`BatchNorm1d` cancels the normalization in the forward output.** Every wrapped convolution has `bias=False` and feeds `BatchNorm1d` directly. Spectral normalization divides the whole weight by one scalar $\sigma$, and `BatchNorm1d` divides its input by a statistic of that input, so $\mathrm{BN}(c z) = \mathrm{BN}(z)$ for every $c > 0$. This holds in train mode up to `eps`. In eval mode it holds only as far as the running statistics were accumulated at the current $\sigma$. `BatchNorm1d` is hard-coded in the blocks, and replacing it is future work. The flag therefore changes the forward output only through the SE layers and the classifier. The convolutional body is not Lipschitz-bounded by the flag.

**The SE gate has no global bound.** The gate $x \cdot \mathrm{sigmoid}(f(\mathrm{mean}(x)))$ has a derivative that grows with $|x|$, even when $f$ is bounded, so the SE blocks do not give a global bound either.

In train mode and from the same weights, the flag changes neither the forward output nor the gradient of the convolutions. Because `BatchNorm1d` removes any scale, a wrapped convolution computes the same function of `original` as an unwrapped one computes of `weight`, up to `eps`. What differs with the flag on is the orthogonal initialization, the extra power-iteration cost, and the checkpoint keys. The orthogonal initialization gives the convolutions a different weight norm than EfficientNet's usual Kaiming initialization, and for these scale-invariant layers the weight norm sets the effective step size, so training with the flag on still differs from training without it. The SE and classifier layers are genuinely normalized.

Per layer, 1x1 convolutions and `nn.Linear` layers are at most 1-Lipschitz, and convolutions with kernel size $k > 1$ are at most $\sqrt{k}$-Lipschitz, because PyTorch normalizes the reshaped kernel matrix, not the convolution operator ([Sedghi et al., 2019]). A depthwise convolution is normalized jointly across its channels, which can shrink a channel with small filters more than that channel alone would need. In training mode, dropout scales by $1/(1-p)$. Section 1.1 of the plan ([[2026.009__efficientnet_spectral_norm__1-plan]]) has the full list.

## Things worth knowing

**Checkpoints do not cross the flag.** With the flag on, a wrapped layer's parameter is renamed from `weight` to `parametrizations.weight.original`, plus two buffers `parametrizations.weight.0._u` and `parametrizations.weight.0._v`. For the stem convolution of `EfficientNetV2BB0`:

```text
flag off: stem.0.weight
flag on:  stem.0.parametrizations.weight.original
          stem.0.parametrizations.weight.0._u
          stem.0.parametrizations.weight.0._v
```

Decide on the flag before training runs you intend to resume from checkpoints. Loading in either direction raises a `RuntimeError` (see Fixing common issues).

**The parameter count is unchanged.** `original` replaces `weight`, and `_u` and `_v` are buffers. A network has the same number of parameters with the flag on and off.

**Wrapping twice is harmless.** `set_spectral_norm` (`dlk/nets/spectral_norm.py`) skips a layer that already has a spectral-norm parametrization.

**`torch.compile` and CUDA are unverified.** A parametrization recomputes the weight on every forward. Only CPU has been tested.

**Changing your mind.** Set `enable_spectral_norm=False` (the default) and rebuild the network; there is nothing else to undo. The old checkpoint loads again.

## Fixing common issues

**`TypeError: block_cls must be MBConv1D or FusedMBConv1D, got <class '__main__.Bad'>`.** A `StageConfig` names a custom `block_cls` (here `Bad`) that subclasses neither block. `NetStyle.for_block` picks the block style by class, so this fails even with the flag off. Subclass `MBConv1D` or `FusedMBConv1D`, accept `style` and `enable_spectral_norm: bool = False` in `__init__`, and wrap the block's layers with `set_spectral_norm` when the flag is set.

**`RuntimeError: Error(s) in loading state_dict for EfficientNetV2BB0: Missing key(s) in state_dict: "stem.0.weight", ...`.** A checkpoint saved with the flag on is being loaded into a network built with the flag off. The reverse direction reports `Missing key(s) in state_dict: "stem.0.parametrizations.weight.original", "stem.0.parametrizations.weight.0._u", ...`. Rebuild the network with the same `enable_spectral_norm` setting the checkpoint was trained under.
