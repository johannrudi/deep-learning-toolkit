# Plan: Spectral Normalization in `ScalableEfficientNet1D` and its Blocks

## Context

**Why.** `MLPResNet` and `ConvResNet` offer `enable_spectral_norm=True` (`docs/features/2026.007__conv_spectral_norm__1-plan.md`). The EfficientNets in `dlk/nets/efficientnet1d.py` do not, so a critic or a composed stem built from them cannot be spectrally normalized by construction. This plan adds the same switch to the EfficientNet family, so that it is ready when `BatchNorm1d` is replaced by a normalization with a bounded gradient (out of scope here).

**Current state.**

- `ConvResNet` threads one boolean through its blocks. `UniversalMultiLevelBlock` wraps each convolution with the private helper `_spectral_norm` (`dlk/nets/conv1d.py`, search for `def _spectral_norm(`), which skips a layer that is already wrapped by checking `get_spectral_norm` (`dlk/nets/utils.py`).
- `set_init_parameters` (`dlk/nets/utils.py`, search for `spectral_norm_and_weight`) initializes a wrapped layer through `parametrizations.weight.original`: orthogonal weight, then a re-sync of the power iteration.
- `ScalableEfficientNet1D._initialize_weights` writes Kaiming and `normal_(0, 0.01)` values into `m.weight`. On a wrapped layer `m.weight` is recomputed from `original` on every access, so these writes would silently have no effect.
- Every convolution in the stem, blocks, and head is followed by `BatchNorm1d` and has `bias=False`. The squeeze-and-excitation (SE) block uses two `nn.Linear` layers (`SqueezeExcitation1DLinear`), and the head ends in an `nn.Linear` classifier.
- The 20 named variants (`EfficientNetV1B0Minimal` to `EfficientNetV2XL`) list their constructor arguments explicitly and forward them to `ScalableEfficientNet1D`.

**Gaps.**

- No `enable_spectral_norm` flag on `MBConv1D`, `FusedMBConv1D`, `SqueezeExcitation1DLinear`, `ScalableEfficientNet1D`, or the named variants.
- `_initialize_weights` does not know about parametrized layers.
- The wrap helper is private to `conv1d.py`; importing `_spectral_norm` from another module would break the no-private-imports rule.
- `tests/nets/test_net_baselines.py` freezes `EfficientNetV1B0Minimal` only, which has no `FusedMBConv1D`. No test pins the `state_dict` keys of an EfficientNet.

**Settled design decisions.**

1. The flag wraps every `nn.Conv1d` and `nn.Linear` of the network: stem convolution, every block convolution, the SE `reduce` and `expand` layers, the head's 1x1 convolution, and the classifier `nn.Linear`. There is one flag for the whole network, as in `MLPResNet`.
2. Each of the 20 named variants gets an explicit `enable_spectral_norm: bool = False` argument, documented and forwarded, in the style of its other arguments.
3. Wrapped layers are initialized with `set_init_parameters` (orthogonal `original`, power iteration re-synced), and their biases are then zeroed to keep EfficientNet's zero-bias convention.
4. The structure mirrors `ConvResNet`: the flag is a constructor argument of each block, and each block wraps its own layers where it builds them.
5. `_spectral_norm` moves to `dlk/nets/utils.py` as the public `set_spectral_norm`, which both `conv1d.py` and `efficientnet1d.py` import.
6. `BatchNorm1d` and the unbounded SE gate stay as they are. The docstrings and the usage doc state their effect (Section 1.1).

**Core principle.** Spectral normalization is a construction-time wrapper around each weighted layer, off by default. With the flag off, every module, parameter name, initialization, and forward output is bit-identical to today.

Consequences, i.e., what needs no change:

- Every `forward` method, since the parametrization is transparent to the call.
- `resolve_input_shape`, `resolve_output_shape`, and the composition code in `dlk/nets/compose.py`.
- `dlk/nets/cli_efficientnet.py`: `_resolve_scaled_channels` checks `isinstance(first_layer, nn.Conv1d)`, which still holds for a parametrized convolution, and the parameter count is unchanged because `original` replaces `weight` and `_u`, `_v` are buffers.
- `round_filters`, `round_repeats`, `MBConvConfig`, and the `get_efficientnet_*_config` builders.
- `SqueezeExcitation1DConv`, which no network uses (Section 6).

## Terminology

- **Spectral norm** $\sigma(W)$: the largest singular value of a matrix $W$, i.e., the most that $W$ can stretch a vector.
- **Spectral normalization** (Miyato et al. 2018): a reparametrization that replaces the trainable weight $W$ by $W / \sigma(W)$ in every forward pass. PyTorch estimates $\sigma$ by one power-iteration step per training forward and stores the iteration vectors $u, v$ as buffers.
- **Parametrization**: PyTorch's mechanism (`torch.nn.utils.parametrize`) that computes `layer.weight` from a stored `parametrizations.weight.original` tensor on access. The wrapped class is a subclass of the original one (`ParametrizedConv1d` is an `nn.Conv1d`), so `isinstance` checks keep matching.
- **Reshaped kernel matrix**: PyTorch normalizes a `Conv1d` weight of shape `(out, in / groups, k)` as a matrix of shape `(out, in / groups · k)`. For a 1x1 convolution this matrix is the operator. For kernel size $k > 1$ the operator norm can exceed $\sigma$ of this matrix by up to a factor $\sqrt{k}$.
- **Depthwise convolution**: a convolution with one group per channel (`groups=channels`), as in `MBConv1D.depthwise_conv`. Its weight has shape `(C, 1, k)`, reshaped to a `(C, k)` matrix. Normalizing this matrix jointly bounds the filter of every channel by 1 in the Euclidean norm, which is stricter than needed because the channels are independent.
- **Scale invariance of a normalization**: a normalization that divides by a statistic of its own input satisfies $\mathrm{BN}(c z) = \mathrm{BN}(z)$ for every $c > 0$, up to `eps`. For `BatchNorm1d` this also holds with a per-channel bias before it.
- **MBConv**, **Fused-MBConv**, **SE**: as defined in the docstrings of `MBConv1D`, `FusedMBConv1D`, and `SqueezeExcitation1DLinear`.

**Correctness fix in `_initialize_weights`.** Add a first branch that catches every wrapped layer before the existing `isinstance` branches, which would otherwise match it and write into the recomputed `m.weight`:

```python
for m in self.modules():
    if get_spectral_norm(m) is not None:
        set_init_parameters(m)
        if m.bias is not None:
            nn.init.zeros_(m.bias)
    elif isinstance(m, nn.Conv1d) or ...:  # existing branches unchanged
```

The existing branches keep handling unwrapped layers, so the flag-off path is unchanged. A standalone block built with the flag keeps PyTorch's default initialization of `original`, as a standalone block does today; `spectral_norm` runs 15 power-iteration steps when it registers.

### 1.1 Lipschitz bound (docstring and usage-doc content)

The docstrings state the flag and point here; the derivation lives in this plan and in the usage doc. Per layer, with the flag on, in eval mode:

- 1x1 convolutions (expansion, projection, head) and `nn.Linear` layers (SE, classifier): $\le 1$, exact.
- Stem convolution ($k = 3$, stride 2, zero padding), fused convolution, and depthwise convolution with kernel size $k$: $\le \sqrt{k}$. Stride only subsamples. For the depthwise convolution, the joint normalization bounds each channel's filter by 1, which gives $\le \sqrt{k}$ per channel.
- `SiLU`: about 1.1-Lipschitz. `Sigmoid`: $1/4$. `AdaptiveAvgPool1d(1)`: $\le 1$.
- Residual sum: $\le 1 + L_\text{branch}$. Dropout scales by $1/(1-p)$ in training mode only.
- `BatchNorm1d`: no bound. Every wrapped convolution feeds a `BatchNorm1d` without a bias in between, and spectral normalization divides the whole weight by one scalar $\sigma$. By scale invariance, `BatchNorm1d` removes this scalar in train and eval mode, up to `eps`. **Until `BatchNorm1d` is replaced, the flag changes the forward output only through the SE layers and the classifier.** It still changes the training dynamics of the convolutions, because the gradient with respect to `original` is scaled by $1/\sigma$.
- SE gate $x \cdot \mathrm{sigmoid}(f(\mathrm{mean}(x)))$: no global bound, because its derivative grows with $|x|$ even when $f$ is bounded.

## 4. Application migration sketch

Opt in with one keyword on any named variant or on `ScalableEfficientNet1D`:

```diff
     "stem_y": EfficientNetV1B0Minimal(
         input_channels=INPUT_CHANNELS,
         input_length=INPUT_LENGTH,
         num_classes=STEM_OUTPUT_SIZE,
+        enable_spectral_norm=True,
     ),
```

A custom `block_cls` in a `StageSpec` must accept the new keyword. The two block classes in the module are the only ones in the toolkit and its examples.

## 10. Risks and edge cases

- **BatchNorm cancels the normalization.** As long as every convolution feeds `BatchNorm1d`, the flag bounds nothing in the convolutional body (Section 1.1). Users may expect a Lipschitz network from the flag; the docstring and usage doc say otherwise.
- **Effective learning rate.** Because `BatchNorm1d` removes $\sigma$ from the output, the wrapped convolutions are scale invariant in `original`, and their gradients shrink as $\sigma$ grows. Training with the flag on may need a different learning rate than without it.
- **Checkpoints.** With the flag on, the wrapped parameters are renamed to `parametrizations.weight.original` plus `_u`, `_v` buffers. Checkpoints do not load across flag settings in either direction.
- **Custom `block_cls`.** A `StageSpec` with a user-defined block class that lacks the `enable_spectral_norm` keyword now fails with `TypeError`, even with the flag off. No such class exists in the toolkit or its examples.
- **Depthwise over-normalization.** The joint normalization of the `(C, k)` matrix can shrink channels with small filters more than needed. This matches the treatment of grouped convolutions in `ConvResNet`.
- **Private torch API.** `set_init_parameters` calls `_SpectralNorm._reshape_weight_to_matrix` and `_power_method`; test 5b covers depthwise and dense convolutions and `Linear` layers.
- **Large variants.** Wrapping every layer of `EfficientNetV2XL` adds one power-iteration step per layer and training forward. Tests use the minimal variants only.
