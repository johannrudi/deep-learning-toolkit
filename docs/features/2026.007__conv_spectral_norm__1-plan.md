# Plan: Spectral Normalization in `ConvResNet` and `UniversalMultiLevelBlock`

## Context

**Why.** `MLPResNet` offers `enable_spectral_norm=True`, which wraps every `nn.Linear` with `torch.nn.utils.parametrizations.spectral_norm` (`dlk/nets/mlp.py`, search for `spectral_norm(`). No convolutional network offers the same switch, so a WGAN critic built from `ConvResNet` cannot be Lipschitz-constrained by construction. The gradient-penalty plan (`docs/features/2026.008__gradient_penalties__1-plan.md`, Context) records this gap. This plan closes it for `dlk/nets/conv1d.py`.

**Current state.**

- Initialization already handles wrapped convolutions. `set_init_parameters` (`dlk/nets/utils.py`, search for `spectral_norm_and_weight`) gives a spectrally normalized layer an orthogonal weight and re-syncs the power iteration. `tests/nets/test_nets_utils.py` covers this for `Linear` and `Conv1d`.
- `UniversalMultiLevelBlock.init_parameters` (`dlk/nets/conv1d.py`, search for `parametrize.is_parametrized(init_modules[-1])`) already skips zeroing a parametrized last convolution.
- A spectrally normalized block can already be built today by passing a `conv` factory that wraps `nn.Conv1d`. `ConvResNet` stores its `conv` argument in `conv_resnet_params["block_kwargs"]["conv"]`, so one factory reaches `input_layer` and every block; setting `conv` inside `block_kwargs` raises `ValueError`. A callable in the config is not serializable, which is one reason to prefer a boolean flag.
- `UniversalMultiLevelBlock.__init__` already has a placeholder parameter `enable_spectral_norm: bool = False  # TODO`, which the block ignores.

**Gaps.**

- No working `enable_spectral_norm` flag on `UniversalMultiLevelBlock` (only the placeholder) or `ConvResNet`.
- No test that a spectrally normalized conv stack is wrapped completely, and no test of the Lipschitz bound of a block.
- No frozen forward baseline for `ConvNeXtBlock`, which inherits the new flag.
- No documentation of what the bound means for convolutions, grouped convolutions, `GroupNorm`, `GELU`, and replicate padding.

**Settled design decisions.**

1. The switch lives in `conv_resnet_params["enable_spectral_norm"]`, next to `use_dropout`. It wraps `input_layer` and is forwarded to every `LevelBlock`. The `MLPResNet` head keeps its own `mlp_resnet_params["enable_spectral_norm"]`, and `ConvResNet` never sets it implicitly.
2. Grouped and depthwise convolutions (the `ConvResNet` input layer, `ConvNeXtBlock.conv_0`) are wrapped like every other convolution. The docstrings state the caveat (see Terminology, *grouped convolution*).
3. `ConvResNet` keeps ignoring unknown keys in `conv_resnet_params`. The silent drop of `"activation"` and `"mlb_kwargs"` in the consumers is listed under unrelated improvements.

**Core principle.** Spectral normalization is a construction-time wrapper around each convolution, off by default. With the flag off, every module, parameter name, initialization, and forward output is bit-identical to today.

Consequences, i.e., what needs no change:

- `set_init_parameters`, `set_zero_parameters`, and `UniversalMultiLevelBlock.init_parameters`, which already handle wrapped convolutions.
- Every `forward` method, since the parametrization is transparent to the call.
- `DownsampleBlock`, `UpsampleBlock`, `LevelBlock`, and `ConvNeXtBlock`, which forward `**block_kwargs` and so receive the flag without edits.
- `MLPResNet` and the gradient-penalty regularizer, which already skips spectrally normalized layers.
- `state_dict` keys of existing checkpoints, which change only when the flag is on.

## Terminology

- **Spectral norm** $\sigma(W)$: the largest singular value of a matrix $W$, i.e., the most that $W$ can stretch a vector. A linear map with $\sigma(W) \le 1$ is 1-Lipschitz.
- **Spectral normalization** (Miyato et al. 2018): a reparametrization that replaces the trainable weight $W$ by $W / \sigma(W)$ in every forward pass. PyTorch estimates $\sigma$ by one power-iteration step per training forward and stores the iteration vectors $u, v$ as buffers.
- **Parametrization**: PyTorch's mechanism (`torch.nn.utils.parametrize`) that computes `layer.weight` from a stored `parametrizations.weight.original` tensor on access. Wrapping renames the trainable parameter in the `state_dict`.
- **Lipschitz constant** $L$ of a function $f$: the smallest $L$ with $\|f(x) - f(y)\| \le L \|x - y\|$ for all $x, y$. A composition's constant is at most the product of its parts' constants, and a sum's is at most the sum of its parts' constants.
- **Reshaped kernel matrix**: PyTorch normalizes a `Conv1d` weight of shape `(out, in / groups, k)` as the matrix of shape `(out, in / groups · k)`. For a 1x1 convolution this matrix is the operator, so the bound is exact. For kernel size $k > 1$ the operator norm of the convolution can exceed $\sigma$ of this matrix by up to a factor $\sqrt{k}$ (Sedghi et al. 2019; Gouk et al. 2021).
- **Grouped convolution**: a convolution with `groups > 1`, which acts as a block-diagonal operator, one block per group. Its operator norm is the maximum over the groups. PyTorch normalizes all groups jointly as one matrix, which bounds each group by 1 but can shrink small groups more than needed. A depthwise convolution has one group per channel.
- **Skip branch**, **main branch**, **drop path**: as defined in the docstring of `UniversalMultiLevelBlock`.

### 1.1 Lipschitz bound of a block (docstring content)

For a block with the flag on, in eval mode, the bound is $L_\text{block} \le s \, (L_\text{skip} + L_\text{main})$ with $s$ = `skip_scale`. Its factors:

- `conv_1`, `conv_2`, and the 1x1 skip convolution: $\le 1$, exact, because a 1x1 convolution is its reshaped kernel matrix.
- `conv_0` with kernel size $k$: $\le \sqrt{k}$ with zero padding. Stride $> 1$ only subsamples and does not increase the bound. Replicate padding of $p$ samples per side adds a factor up to $\sqrt{1 + p}$.
- Resizing the skip branch with `area` interpolation: $\le 1$.
- Activation: `nn.ReLU` and `nn.LeakyReLU` are 1-Lipschitz; `nn.GELU` (the block default) is about 1.13-Lipschitz.
- Normalization: `GroupNorm` and `ChannelLayerNorm` divide by a per-sample standard deviation and have no Lipschitz bound. A strictly bounded block needs `normalization=False`.
- Dropout and drop path scale activations by $1/(1-p)$ in training mode only.

With `normalization=False`, `activation=nn.ReLU()`, zero padding, and `skip_scale=0.5`, a block with a skip connection satisfies $L_\text{block} \le 0.5 \, (1 + \sqrt{k})$. The docstring states this bound and does not enforce any of these settings, in line with `ResidualBlock`, which keeps `LayerNorm` under `enable_spectral_norm=True`.

## 3. Application migration sketch

When building a `ConvResNet`, opt in with one key:

```diff
     conv_resnet_params = {
         "channels_mult": net_params["conv_layer_sizes"],
         "kernels": n_conv_layers * [kernel],
         "activation": activation_fn,
         "use_dropout": use_dropout,
+        "enable_spectral_norm": net_params.get("spectral_norm", False),
         "mlb_kwargs": mlb_kwargs,
     }
     ...
     mlp_resnet_params = {
         ...
         "use_dropout": use_dropout,
+        "enable_spectral_norm": net_params.get("spectral_norm", False),
         "output_layer_activation": output_layer_activation,
     }
```

A strict bound also needs

```
block_kwargs={
    "normalization": False,
    "activation": nn.ReLU(),
    "skip_scale": 0.5,
    "conv_kwargs": {"padding_mode": "zeros"}
}
```

## 9. Risks and edge cases

- **Checkpoints.** With the flag on, the conv parameters are renamed to `parametrizations.weight.original` plus `_u`, `_v` buffers. Checkpoints from networks without the flag do not load into networks with it, and the reverse also fails. The usage doc states this.
- **Weak bound for large kernels.** $\sqrt{k}$ per level compounds over levels. Users who need a tight bound should prefer small `kernels`, or add the regularizer of the 2026.008 plan, which penalizes the reshaped norm and so has the same gap.
- **Private torch API.** `set_init_parameters` calls `_SpectralNorm._reshape_weight_to_matrix` and `_power_method`. Grouped convolutions go through the same calls; test 4c covers them.
- **Training-mode power iteration.** $\sigma$ is estimated with one step per training forward, so right after initialization it is accurate only because `set_init_parameters` re-syncs $u, v$. Eval-mode forwards do not update $u, v$.
- **Normalization and GELU defaults.** The block defaults (`GroupNorm`, `GELU`) void a strict bound. The flag alone does not make a `ConvResNet` 1-Lipschitz; the docstring and usage doc say so.
- **`torch.compile`.** Parametrizations recompute the weight in every forward; compile compatibility is unverified (Section 8, pending).
