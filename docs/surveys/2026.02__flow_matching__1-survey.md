# Flow Matching: path.sample, conditional velocity, and alternative parameterizations

This document expands on three topics that appear in a standard continuous flow matching
training loop built with the `flow-matching` library (v1.0.10):

1. What `AffineProbPath.sample` computes and what each field of `PathSample` means.
2. Why `dx_t` (the conditional velocity) is a valid training target for the marginal
   velocity field.
3. The alternative model parameterizations supported by `AffineProbPath` and how to
   use them.

---

## 1. What `path.sample` computes

### The affine interpolation

`AffineProbPath` defines a family of probability paths parameterized by two
time-dependent scalar schedules, `alpha_t` and `sigma_t`, via the affine interpolation:

```
x_t = alpha_t * x_1 + sigma_t * x_0
```

where `x_0` is a sample from the source distribution (typically standard Gaussian noise),
`x_1` is a sample from the target data distribution, and `t` is drawn uniformly from
`[0, 1]`. The schedules satisfy `alpha_0 = 0`, `alpha_1 = 1`, `sigma_0 = 1`, `sigma_1 = 0`
so that at `t=0` we recover pure noise and at `t=1` we recover pure data.

The corresponding conditional velocity — the time derivative of `x_t` with respect to
`t`, holding `x_0` and `x_1` fixed — is:

```
dx_t = d_alpha_t * x_1 + d_sigma_t * x_0
```

where `d_alpha_t` and `d_sigma_t` are the time derivatives of the schedules.

When `path.sample(x_0=x_0, x_1=x_1, t=t)` is called, the library:

1. Calls the scheduler to obtain `alpha_t`, `sigma_t`, `d_alpha_t`, `d_sigma_t` for
   each element of the batch.
2. Broadcasts those scalars to the data shape (via `expand_tensor_like`).
3. Computes `x_t` and `dx_t` with the formulas above.
4. Returns a `PathSample` dataclass holding `(x_0, x_1, t, x_t, dx_t)`.

### The CondOT scheduler

`CondOTScheduler` is the most common choice. It sets:

```
alpha_t = t          d_alpha_t = 1
sigma_t = 1 - t      d_sigma_t = -1
```

Substituting into the general formulas:

```
x_t  = t * x_1 + (1 - t) * x_0      # straight-line interpolation
dx_t = x_1 - x_0                     # constant velocity along each sample pair
```

This is the Conditional Optimal Transport (CondOT) path: the interpolation between
`x_0` and `x_1` is a straight line traversed at constant speed. The training target
`dx_t` does not depend on `t` and equals the displacement from source to target.

### Other available schedulers

The library ships several additional schedulers, all of which are drop-in replacements
for `CondOTScheduler` in an `AffineProbPath`:

| Scheduler               | alpha_t                       | sigma_t                        | Notes                                        |
|-------------------------|-------------------------------|--------------------------------|----------------------------------------------|
| `CondOTScheduler`       | `t`                           | `1 - t`                        | Straight-line, CondOT path                   |
| `PolynomialConvexScheduler(n)` | `t^n`                  | `1 - t^n`                      | Slows/accelerates approach to x_1            |
| `CosineScheduler`       | `sin(pi/2 * t)`               | `cos(pi/2 * t)`                | Cosine interpolation; smoother near t=1      |
| `LinearVPScheduler`     | `t`                           | `sqrt(1 - t^2)`                | Variance-preserving; keeps ||x_t|| constant  |
| `VPScheduler`           | `exp(-T/2)`                   | `sqrt(1 - exp(-T))`            | Matches DDPM variance-preserving diffusion   |

The choice of scheduler determines the geometry of the probability path and affects
training dynamics, but not the structure of the training loop.

## 2. Conditional versus marginal velocity, and the flow matching theorem

### The marginal velocity field

A flow model learns a time-dependent vector field `v_theta(x, t)` that, when integrated
as an ODE from `t=0` to `t=1`, transports noise `x_0 ~ p_0` to data `x_1 ~ p_1`. The
ideal target is the **marginal velocity field**:

```
u_t(x) = E[ dx_t | x_t = x ]
```

This expectation is taken over all source-target pairs `(x_0, x_1)` consistent with
`x_t = x` under the coupling `pi(x_0, x_1)`. Computing it directly requires integrating
over the data manifold conditioned on a specific point `x`, which is intractable in
practice.

### The conditional velocity field

The **conditional velocity** is the velocity for a single fixed pair `(x_0, x_1)`:

```
u_t(x_t | x_0, x_1) = dx_t = d_alpha_t * x_1 + d_sigma_t * x_0
```

This is cheap to compute: given a batch of `(x_0, x_1)` pairs and a time `t`, it is a
closed-form expression. The key insight of flow matching is that we do not need the
marginal velocity to train the model.

### The flow matching theorem

Define two loss functions:

```
L_FM(theta)  = E_{t, x_t ~ p_t}          [ || v_theta(x_t, t) - u_t(x_t)  ||^2 ]
L_CFM(theta) = E_{t, (x_0,x_1) ~ pi, x_t | x_0,x_1 } [ || v_theta(x_t, t) - dx_t ||^2 ]
```

`L_FM` is the ideal objective (marginal velocity regression) and `L_CFM` is the
conditional flow matching objective used in the training loop. They are related by:

```
L_CFM(theta) = L_FM(theta) + C
```

where `C = E[ || dx_t - u_t(x_t) ||^2 ]` is a constant that depends only on the data
distribution and the path — not on the model parameters `theta`. Because `C` is
independent of `theta`, the gradients of the two losses are identical:

```
grad_theta L_CFM(theta) = grad_theta L_FM(theta)
```

Therefore, minimizing `L_CFM` over `theta` is equivalent to minimizing `L_FM`. This
makes training tractable: instead of estimating the intractable marginal velocity, we
regress on the conditional velocity of individual sample pairs, and the model implicitly
learns the marginal field.

### Intuition

At a given point `(x, t)`, many different source-target pairs `(x_0, x_1)` may pass
through `x`. Each pair contributes a conditional velocity `dx_t`. The model output
`v_theta(x, t)` is a single vector that must reconcile all of them. The MSE loss
drives `v_theta(x, t)` toward the weighted average of all conditional velocities
passing through `x`, which is exactly the marginal velocity `u_t(x)`.

The training loop therefore works correctly even though `dx_t` for any individual sample
is not the marginal velocity — it is merely a noisy, unbiased estimate of it.

## 3. Alternative model parameterizations

### Three representations of the same signal

For an affine path, the triplet `(x_0, x_1, t)` determines `x_t` uniquely. Given `x_t`
and `t`, knowing any one of `x_0`, `x_1`, or `dx_t` determines the other two. A model
can therefore be trained to predict any one of:

- **Velocity** `v_theta(x_t, t) ≈ dx_t` — directly regress the conditional velocity.
- **Target (x-prediction)** `x1_theta(x_t, t) ≈ x_1` — predict the clean data point.
- **Epsilon (noise prediction)** `eps_theta(x_t, t) ≈ x_0` — predict the source noise.

All three are equivalent in theory; they differ in scale and curvature of the loss
surface, which can affect training stability and convergence speed in practice.

### Conversion formulas

`AffineProbPath` provides closed-form methods to convert between representations. Each
method takes `(input, x_t, t)` and returns the converted representation by solving the
affine system.

**Target → velocity** (`target_to_velocity(x_1, x_t, t)`)

Solve for `dx_t` given `x_1` and `x_t`:

```
a_t = d_sigma_t / sigma_t
b_t = (d_alpha_t * sigma_t - d_sigma_t * alpha_t) / sigma_t

velocity = a_t * x_t + b_t * x_1
```

For CondOT this simplifies to:

```
velocity = (x_1 - x_t) / (1 - t)
```

**Epsilon → velocity** (`epsilon_to_velocity(epsilon, x_t, t)`)

Solve for `dx_t` given `x_0` (epsilon) and `x_t`:

```
a_t = d_alpha_t / alpha_t
b_t = (d_sigma_t * alpha_t - d_alpha_t * sigma_t) / alpha_t

velocity = a_t * x_t + b_t * epsilon
```

For CondOT this simplifies to:

```
velocity = (x_t - epsilon) / t
```

**Velocity → target** (`velocity_to_target(velocity, x_t, t)`)

Solve for `x_1` given `dx_t` and `x_t`:

```
a_t = -d_sigma_t / (d_alpha_t * sigma_t - d_sigma_t * alpha_t)
b_t =  sigma_t   / (d_alpha_t * sigma_t - d_sigma_t * alpha_t)

x_1 = a_t * x_t + b_t * velocity
```

For CondOT: `x_1 = x_t + (1 - t) * velocity`

**Velocity → epsilon** and **target → epsilon** / **epsilon → target** are also provided
with analogous derivations.

### How to use conversions in the training loop

If the model predicts `x_1` instead of the velocity, the loss can still be written as
an MSE against `path_sample.dx_t` by converting the prediction first:

```python
path_sample = path.sample(t=t, x_0=x_0, x_1=x_1)

# model predicts x_1 directly
x1_pred = model(path_sample.x_t, path_sample.t)

# convert to velocity to use the standard CFM loss
v_pred = path.target_to_velocity(x1_pred, path_sample.x_t, path_sample.t)
loss = F.mse_loss(v_pred, path_sample.dx_t)
```

Alternatively, the loss can be written directly in the x-prediction space by converting
the target instead of the prediction:

```python
x1_target = path.velocity_to_target(path_sample.dx_t, path_sample.x_t, path_sample.t)
loss = F.mse_loss(x1_pred, x1_target)
```

Both formulations are equivalent up to a scalar weighting factor arising from the
Jacobian of the conversion, which can affect the effective learning rate per time step.

### Practical notes

- For CondOT, the velocity target `dx_t = x_1 - x_0` has variance independent of `t`,
  while the x-prediction target `x_1` becomes progressively easier to predict as `t → 1`
  (the signal `x_t` approaches `x_1`). This variance profile affects which parameterization
  trains more stably.
- The built-in `loss` module (`flow_matching.loss`) contains `MixturePathGeneralizedKL`
  which applies only to **discrete** flow matching. For continuous flow matching there is
  no dedicated loss class; the manual MSE shown above is the standard approach.
- At inference time, the model wrapped in `ModelWrapper` is passed to `ODESolver`, which
  always expects the model to output a **velocity**, regardless of the parameterization
  used during training. If the model was trained as an x-predictor or epsilon-predictor,
  the wrapper's `forward` method must include the appropriate conversion call before
  returning.
